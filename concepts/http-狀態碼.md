# 概念卡：HTTP 狀態碼（CRUD 對照）

> 一句話：狀態碼是伺服器用「三位數字」告訴前端「這次請求結果如何」。記住幾個常用的，API 就能講出讓人一看就懂的話。

---

## 一、五大類

| 開頭 | 意思 | 例子 |
|---|---|---|
| `2xx` | 成功 | 200、201、204 |
| `3xx` | 重新導向 | 301、302 |
| `4xx` | **你（前端）**錯了 | 400、401、403、404 |
| `5xx` | **我（伺服器）**錯了 | 500 |

新手最該分清楚的是 `4xx` vs `5xx`：資料填錯、沒登入、找不到 → 4xx；程式自己爆了 → 5xx。

---

## 二、CRUD 常用對照

| 操作 | HTTP 方法 | 成功 | 說明 | 失敗 |
|---|---|---|---|---|
| **Create** | `POST` | **201 Created** | 已建立新資源 | 400（驗證失敗）、409（重複） |
| **Read** | `GET` | **200 OK** | 回傳資源 | 404（找不到） |
| **Update** | `PUT` / `PATCH` | **200 OK** 或 **204 No Content** | 200 回傳更新後資料；204 不回主體 | 400、404 |
| **Delete** | `DELETE` | **204 No Content** | 刪除成功、不回主體 | 404 |

> 這些是業界共識、非硬性規定，但照著做能讓 API 使用者一眼看懂結果。

---

## 三、容易混淆：PUT vs PATCH

兩個都是「更新」，但語義不同——這是面試和實務都常考的點：

| | PUT | PATCH |
|---|---|---|
| 意思 | **整份替換** | **部分更新** |
| 你要送 | 資源的**完整**內容 | 只送**要改的**欄位 |
| 範例 | 連 title、completed 全部一起送 | 只送 `{ "completed": true }` |
| 冪等性 | 是（送同樣內容幾次結果都一樣） | 通常是 |

本課程的 todo app 用 **PATCH**——因為我們常常只想改「完成狀態」，不想每次都把整筆重送一遍。

---

## 延伸
- `201 Created` 慣例上會在回應的 `Location` header 附上新資源的網址。
- `401 Unauthorized`（沒登入/沒帶憑證）和 `403 Forbidden`（有登入但沒權限）不一樣，到 [M6 JWT]、[M7 OAuth] 會用到。
