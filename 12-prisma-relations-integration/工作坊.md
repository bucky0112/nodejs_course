# 第 12 堂工作坊：用 Prisma 做出清單與標籤

第 9 堂用 SQL 建過 `lists`、`tags`、`todo_tags` 三張表，也用 JOIN 查過它們。這一堂用 Prisma 把同樣的關聯做進 todo app：

- **清單（1:N）**：一個清單有多筆 todo，一筆 todo 最多屬於一個清單。
- **標籤（M:N）**：一筆 todo 可以貼多個標籤，一個標籤也可以貼在多筆 todo 上。

## 步驟 0：先畫出要做的 API

照第 5 堂的習慣，先寫 API 對照表：

| 方法 | 路徑 | 行為 | 狀態碼 |
|---|---|---|---|
| GET | `/lists` | 列出所有清單 | 200 |
| GET | `/lists/:id` | 單一清單，**連同底下的 todo** | 200 / 404 |
| POST | `/lists` | 新增清單 | 201 / 400 |
| DELETE | `/lists/:id` | 刪除清單（底下的 todo 保留，變成沒有清單） | 204 / 404 |
| GET | `/tags` | 列出所有標籤 | 200 |
| POST | `/tags` | 新增標籤，名稱不能重複 | 201 / 400 / 409 |
| POST / PATCH | `/todos`、`/todos/:id` | 多一個 `listId` 欄位 | 同前 |
| GET | `/todos`、`/todos/:id` | 回應**連同清單和標籤** | 同前 |
| POST | `/todos/:id/tags` | 替 todo 貼標籤，body 是 `{ "tagId": 1 }` | 201 / 400 / 404 |
| DELETE | `/todos/:id/tags/:tagId` | 撕掉標籤 | 204 / 404 |

新的狀態碼 **409 Conflict**：請求本身沒問題，但跟現有資料衝突（標籤名稱重複）。

`/todos/:id/tags` 是**巢狀資源**：「某筆 todo 的標籤」。網址從左讀到右，就是資源的從屬關係。

## 步驟 1：在 schema 加上關聯

打開 `prisma/schema.prisma`，新增 `List`、`Tag`、`TodoTag` 三個 model，並在 `Todo` 加上關聯欄位：

```prisma
// 清單：一個清單有多筆 todo（1:N 的「一」邊）
model List {
  id    Int    @id @default(autoincrement())
  name  String @db.VarChar(100)
  todos Todo[] // 關聯欄位：不會變成資料庫的欄位，只是讓 Prisma 知道可以從清單找到 todo

  @@map("lists")
}

model Todo {
  id        Int       @id @default(autoincrement())
  title     String    @db.VarChar(200)
  completed Boolean   @default(false)
  createdAt DateTime  @default(now()) @map("created_at") @db.Timestamptz
  // 1:N 的「多」邊：listId 是真正存在資料庫裡的外鍵欄位；list 是關聯欄位
  listId    Int?      @map("list_id")
  list      List?     @relation(fields: [listId], references: [id], onDelete: SetNull)
  todoTags  TodoTag[]

  @@map("todos")
}

model Tag {
  id       Int       @id @default(autoincrement())
  name     String    @unique @db.VarChar(50)
  todoTags TodoTag[]

  @@map("tags")
}

// todo 與 tag 的中介表（M:N），跟第 9 堂的 todo_tags 一樣
model TodoTag {
  todoId Int  @map("todo_id")
  tagId  Int  @map("tag_id")
  todo   Todo @relation(fields: [todoId], references: [id], onDelete: Cascade)
  tag    Tag  @relation(fields: [tagId], references: [id], onDelete: Cascade)

  @@id([todoId, tagId]) // 複合主鍵：同一組 (todo, tag) 不重複
  @@map("todo_tags")
}
```

對照第 9 堂的 SQL：

| 第 9 堂 SQL | schema.prisma |
|---|---|
| `list_id INT REFERENCES lists(id) ON DELETE SET NULL` | `listId Int? @map("list_id")` 加上 `@relation(..., onDelete: SetNull)` |
| `name VARCHAR(50) NOT NULL UNIQUE` | `name String @unique @db.VarChar(50)` |
| `PRIMARY KEY (todo_id, tag_id)` | `@@id([todoId, tagId])` |
| `REFERENCES todos(id) ON DELETE CASCADE` | `@relation(..., onDelete: Cascade)` |

`Int?` 的 `?` 代表**可以是 NULL**：todo 不一定要屬於某個清單。

> 🧠 外鍵欄位和關聯欄位的差別、為什麼中介表要寫成一個 model → [概念卡：Prisma 關聯查詢](../concepts/prisma-關聯查詢.md)

## 步驟 3：清單與標籤的三層

照第 6 堂的結構，各自新增 service、controller、routes，並掛到 `src/routes/index.js`。

`src/services/lists.service.js` 裡，「單一清單連同底下的 todo」用 `include`：

```js
async function findOrThrow(id, include) {
  if (!Number.isInteger(id)) throw new HttpError(404, '找不到這個清單')
  const list = await prisma.list.findUnique({ where: { id }, include })
  if (!list) throw new HttpError(404, '找不到這個清單')
  return list
}

// 1:N：一次撈出清單和底下所有 todo
export async function getList(id) {
  return findOrThrow(id, { todos: { orderBy: { id: 'asc' } } })
}
```

`include: { todos: true }` 的意思是「順便把關聯欄位 `todos` 的資料撈出來」。沒有 `include`，回傳的清單就只有 `id` 和 `name`。

`src/services/tags.service.js` 新增標籤時，先檢查名稱有沒有重複：

```js
export async function createTag({ name } = {}) {
  if (typeof name !== 'string' || name.trim() === '') {
    throw new HttpError(400, 'name 必填，且必須是非空字串')
  }
  // tags.name 有 UNIQUE 限制：先檢查，重複就回 409，而不是讓資料庫報錯變成 500
  const existing = await prisma.tag.findUnique({ where: { name: name.trim() } })
  if (existing) throw new HttpError(409, '這個標籤已經存在')
  return prisma.tag.create({ data: { name: name.trim() } })
}
```

> 💡 `findUnique` 只能用 `@id` 或 `@unique` 的欄位查詢。`name` 加了 `@unique`，所以可以用。

其餘的 `listLists`、`createList`、`deleteList`、`listTags` 以及 controller、routes，照第 6 堂的模式自己寫，寫完對照[完成版](./完成版/src/)。

> ✅ **檢查點 B**：`POST /lists`、`GET /lists`、`POST /tags`、`GET /tags` 都能用；同名標籤新增第二次回 409。

## 步驟 4：todo 帶出清單和標籤

在 `src/services/todos.service.js` 最上面定義一次「要帶出哪些關聯」，所有查 todo 的地方共用：

```js
// 撈 todo 時一起帶出所屬清單和標籤（標籤要穿過中介表 todoTags）
const withRelations = {
  list: true,
  todoTags: { include: { tag: true }, orderBy: { tagId: 'asc' } },
}

// 把 todoTags: [{ todoId, tagId, tag: {...} }] 攤平成 tags: [{...}]，前端比較好用
function shapeTodo(todo) {
  const { todoTags, ...rest } = todo
  return { ...rest, tags: todoTags.map((link) => link.tag) }
}
```

然後把每個查詢加上 `include: withRelations`，回傳前經過 `shapeTodo`：

```js
export async function listTodos({ completed } = {}) {
  const where = completed === undefined ? {} : { completed: completed === 'true' }
  const todos = await prisma.todo.findMany({ where, include: withRelations, orderBy: { id: 'asc' } })
  return todos.map(shapeTodo)
}
```

新增和更新也要支援 `listId`。`listId` 可以是數字（放進某個清單）或 `null`（移出清單），有給數字就要確認清單存在：

```js
async function assertListId(listId) {
  if (listId === null) return
  if (!Number.isInteger(listId)) throw new HttpError(400, 'listId 必須是整數或 null')
  const list = await prisma.list.findUnique({ where: { id: listId } })
  if (!list) throw new HttpError(400, '指定的 listId 不存在')
}
```

> 💡 為什麼 `listId` 不存在回 **400** 而不是 404？因為網址上的資源（這筆 todo）是存在的，錯的是**請求的內容**。404 留給「網址指的東西不存在」。

完整的 `createTodo`、`updateTodo` 見[完成版](./完成版/src/services/todos.service.js)。

> ✅ **檢查點 C**：`POST /todos` 帶 `{"title":"寫報告","listId":1}`，回應裡有 `"list":{"id":1,"name":"工作"}` 和 `"tags":[]`；`listId` 給不存在的數字回 400。

## 步驟 5：貼標籤、撕標籤

貼標籤，就是在中介表新增一列：

```js
// M:N：替 todo 貼上一個標籤（在中介表新增一列）
export async function addTagToTodo(todoId, tagId) {
  await findOrThrow(todoId)
  if (!Number.isInteger(tagId)) throw new HttpError(400, 'tagId 必須是整數')
  const tag = await prisma.tag.findUnique({ where: { id: tagId } })
  if (!tag) throw new HttpError(404, '找不到這個標籤')
  // upsert：已經貼過就不重複新增
  await prisma.todoTag.upsert({
    where: { todoId_tagId: { todoId, tagId } },
    create: { todoId, tagId },
    update: {},
  })
  return getTodo(todoId)
}
```

- `upsert` = update + insert：找得到就更新（這裡 `update: {}` 什麼都不改），找不到就新增。同一個標籤貼兩次不會出錯。
- `todoId_tagId` 是 Prisma 替複合主鍵 `@@id([todoId, tagId])` 自動取的名字。

撕標籤，就是刪掉中介表的那一列：

```js
// M:N：撕掉一個標籤（刪除中介表的那一列；todo 和 tag 本身都還在）
export async function removeTagFromTodo(todoId, tagId) {
  await findOrThrow(todoId)
  if (!Number.isInteger(tagId)) throw new HttpError(404, '這筆 todo 沒有這個標籤')
  const { count } = await prisma.todoTag.deleteMany({ where: { todoId, tagId } })
  if (count === 0) throw new HttpError(404, '這筆 todo 沒有這個標籤')
}
```

> ⚠️ `where` 一定要**同時**有 `todoId` 和 `tagId`。只寫 `todoId`，這筆 todo 的標籤會全部被撕光。

在 `todos.controller.js` 和 `todos.routes.js` 加上對應的兩個路由：

```js
// todos.routes.js
todosRouter.post('/:id/tags', todosController.addTag)
todosRouter.delete('/:id/tags/:tagId', todosController.removeTag)
```

> ✅ **檢查點 D**：替 todo 貼上標籤後，`GET /todos/:id` 的 `tags` 有它；撕掉後消失，再撕一次回 404。

## 步驟 6：驗證關聯的刪除規則

schema 裡設定的 `onDelete` 規則，實際跑一次看看：

```bash
# 刪除清單：底下的 todo 保留，list 變成 null（SetNull）
curl -i -X DELETE http://localhost:3000/lists/1
curl http://localhost:3000/todos/1

# 刪除 todo：它在 todo_tags 的關聯列一起被刪掉（Cascade），標籤本身還在
curl -i -X DELETE http://localhost:3000/todos/1
psql -d todo_app -c 'SELECT * FROM todo_tags'
curl http://localhost:3000/tags
```
