# 課堂練習：自己用 Drizzle 長出一張新表，從 schema 到 CRUD 走一遍

> 這不是工作坊的延伸，而是**把這章的核心重點再走一遍**——但這次沒有逐步指引，你得自己寫。
>
> 核心重點：用 Drizzle 定義 schema → `generate` 產生 migration → `migrate` 套用到資料庫 → 用 ORM（不是手寫 SQL 字串）做 CRUD。

工作坊帶你把 `todos` 接上 PostgreSQL。現在你要在**同一個專案**裡，自己長出一張全新的表 `notes`（隨手筆記），從定義 schema、跑一次 migration，到寫完整 CRUD，親手把這套流程走一遍。

> ⚠️ 這張 `notes` 表跟 `todos` 沒有任何關聯（外鍵、JOIN 留到 [M3]）。這裡只練「單表，從零到 CRUD」。

---

## 任務

### 1. 定義 schema

在 `src/db/schema.js` 裡，**新增**一個 `notes` 表（不要動到 `todos`）。欄位規格：

| 欄位 | 型別 | 規格 |
|---|---|---|
| `id` | integer | 主鍵，自動遞增（跟 `todos` 同款寫法） |
| `text` | varchar(500) | 不可為空 |
| `pinned` | boolean | 不可為空，預設 `false` |
| `createdAt` | timestamp（含時區） | 不可為空，預設現在時間；資料庫欄名 `created_at` |

### 2. 跑一次 migration

- 用 `npm run generate` 比對 schema，產生新的 migration SQL。
- 用 `npm run migrate` 套用到資料庫。
- 打開 `drizzle/` 底下**新產生的那支 `.sql`**，確認裡面有 `CREATE TABLE "notes"`，欄位與你寫的規格一致。

### 3. 寫 `notes` 的 CRUD 路由

在 `app.js` 裡，比照 `todos` 的寫法，加上五個 `async` 路由（全部用 Drizzle 查詢，**不要手拼 SQL 字串**）：

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/notes` | 回傳全部 notes |
| GET | `/notes/:id` | 回傳單筆；找不到回 404 |
| POST | `/notes` | 新增一筆 note |
| PATCH | `/notes/:id` | 更新 `text` 或切換 `pinned` |
| DELETE | `/notes/:id` | 刪除一筆 |

**明確規格**（這幾條就是這章重點，別漏）：

- 新增成功回 **201**，回傳剛建立的那筆（用 `.returning()` 拿）。
- 新增時若 `text` 缺少或是空字串，回 **400** 加一段 JSON 錯誤訊息。
- `PATCH` 時 `pinned` 若不是布林值，回 **400**；沒提供任何要更新的欄位也回 **400**。
- 任何 `:id` 找不到（update / delete / 單筆查詢），回 **404**。
- 刪除成功回 **204**（沒有 body）。
- 路由全部是 `async`，但**不用包 try/catch**（Express 5 會自動轉交）。

> 💡 卡在「`generate` 跟 `migrate` 到底差在哪」→ 回去翻 [概念卡：Drizzle Migration](../concepts/drizzle-migration.md)。卡在「為什麼是這個狀態碼」→ [概念卡：HTTP 狀態碼](../concepts/http-狀態碼.md)。不要直接照抄 `todos` 的路由——憑記憶寫，寫不出來才回去看，這樣才練得到。

## 進階（行有餘力）

- 讓 `GET /notes?pinned=true` 用 Drizzle 的 `where(eq(notes.pinned, true))` 過濾。
- 在 schema 幫 `notes` 加一個 `color`（varchar）欄位，再跑一次 `generate` + `migrate`，觀察這次產生的 migration **只有 `ALTER TABLE`**，不是整張重建——體會 migration 是「累加」的。

## 自我檢核

先把 schema 與 migration 跑起來，再把伺服器跑起來，用下面的指令逐條驗。**全過才算完成**：

```bash
# 0. 產生並套用 migration（schema 改完後）
npm run generate
npm run migrate
# → 確認 drizzle/ 多了一支含 CREATE TABLE "notes" 的 .sql

npm run dev

# 1. 新增一筆 → 應回 201，body 是剛建立的 note（含資料庫給的 id）
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{"text":"記得買牛奶"}'

# 2. 缺 text → 應回 400
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{}'

# 3. 列出全部 → 應回 200 + 陣列
curl -i http://localhost:3000/notes

# 4. 切換 pinned → 應回 200，pinned 變 true
curl -i -X PATCH http://localhost:3000/notes/1 -H "Content-Type: application/json" -d '{"pinned":true}'

# 5. pinned 給字串 → 應回 400
curl -i -X PATCH http://localhost:3000/notes/1 -H "Content-Type: application/json" -d '{"pinned":"yes"}'

# 6. 刪一筆不存在的 → 應回 404
curl -i -X DELETE http://localhost:3000/notes/999
```

- [ ] 0. `generate` 在 `drizzle/` 產生了含 `CREATE TABLE "notes"` 的新 migration，`migrate` 成功套用
- [ ] 1. 新增成功是 `201`，且回傳的 note 帶有資料庫給的 `id`
- [ ] 2. 缺 `text` 回 `400` 且有 JSON 錯誤訊息
- [ ] 3. 列表回 `200` 且是陣列
- [ ] 4. `PATCH` 切 `pinned` 成功（`200`，`pinned` 變 `true`）
- [ ] 5. `pinned` 型別錯回 `400`
- [ ] 6. 刪不存在的回 `404`

> 七條全綠，代表你已經能獨立把一張新表從 schema、migration 到 CRUD 整套走完，不只是跟著工作坊抄 `todos`。
