# 課堂練習：交易、index、正規化各走一次

> 這不是工作坊的延伸，而是**把這堂的三件事各自再走一遍**——但這次沒有逐步指引，你得自己判斷、自己寫。

> 核心重點：什麼時候該包交易、怎麼用 `EXPLAIN` 判斷 index 有沒有用、怎麼把重複的資料拆成多張表。

## 任務 1：交易——安全地合併兩個清單

情境：使用者想把「生活」清單併進「學習」清單，然後刪掉「生活」。這件事要分成兩步：

1. 把「生活」底下的 todo 改到「學習」
2. 刪掉「生活」這個清單

**明確規格**：

- 兩步要包在**同一個交易**裡。
- 先完整走一次、但最後用 **`ROLLBACK`** 結束，確認資料完全沒變。
- 再完整走一次，這次用 **`COMMIT`** 結束。
- 在交易裡、`COMMIT` 之前，自己下 `SELECT` 確認結果對了才 `COMMIT`。
- 想一想：如果第 1 步和第 2 步的**順序反過來**，會發生什麼事？（看第 9 堂 schema 裡 `list_id` 的 `ON DELETE` 設定）

## 任務 2：index——幫「未完成、最新的 20 筆」加速

todo app 首頁最常跑的查詢是：

```sql
SELECT id, title, created_at
FROM todos
WHERE completed = false
ORDER BY created_at DESC
LIMIT 20;
```

**明確規格**：

- 先用 `generate_series` 灌至少 10 萬筆 todo（標題要能讓你事後一次刪乾淨），並執行 `ANALYZE todos;`。
- 用 `EXPLAIN ANALYZE` 記下這條查詢**目前**的計畫和 `Execution Time`。
- 自己決定要建什麼 index（建在哪個欄位、一個欄位還是兩個欄位），建完再跑一次 `EXPLAIN ANALYZE` 比較。
- 試過的 index 如果沒效，用 `DROP INDEX` 拿掉再試別的；最後只留下你認為最好的那一個。
- 做完把灌進去的資料和你建的 index 都清掉。

## 任務 3：正規化——把標籤字串拆成多對多

先在 `psql` 裡貼上這張「沒拆開」的表（這是題目給的資料）：

```sql
CREATE TABLE practice_todo_tags_flat (
  todo_title VARCHAR(200) NOT NULL,
  tag_name   VARCHAR(50)  NOT NULL
);

INSERT INTO practice_todo_tags_flat (todo_title, tag_name) VALUES
  ('寫專案週報',     '緊急'),
  ('寫專案週報',     '工作'),
  ('修登入頁的 bug', '緊急'),
  ('修登入頁的 bug', '工作'),
  ('修登入頁的 bug', '程式'),
  ('學會 SQL JOIN',  '程式'),
  ('學會 SQL JOIN',  '長期');
```

一筆 todo 可以有很多標籤、一個標籤也會貼在很多 todo 上，這是**多對多**。

**明確規格**：

- 拆成**三張表**：todo、標籤、中介表。表名都用 `practice_` 開頭，不要動到第 9 堂的 `todos` / `tags` / `todo_tags`。
- 每張表要有主鍵；標籤名稱不能重複；中介表要有指向另外兩張表的外鍵，且同一組 (todo, 標籤) 不能重複。
- 用 `INSERT ... SELECT` 把 `practice_todo_tags_flat` 的資料搬進三張新表（不要手動一筆一筆打 id）。
- 寫一條 JOIN 把三張表拼回「todo 標題 + 標籤名稱」，結果要跟 `practice_todo_tags_flat` 對得起來。

## 自我檢核

**全部打勾才算完成**：

任務 1
- [ ] `ROLLBACK` 那一輪結束後，「生活」清單還在，它底下的 todo 數量跟開始前一樣。
- [ ] `COMMIT` 那一輪結束後，`lists` 只剩 2 個清單（工作、學習），原本「生活」的 todo 現在都在「學習」底下，**todo 總數沒有少**。
- [ ] 說得出「順序反過來」會讓那些 todo 的 `list_id` 變成什麼。

任務 2
- [ ] 灌資料後、建 index 前，計畫裡看得到 `Seq Scan`（也可能是 `Parallel Seq Scan`）和 `Sort`。
- [ ] 建 index 後，計畫裡看得到 `Index Scan`（或 `Index Scan Backward`、`Bitmap Index Scan`），`Execution Time` 明顯變短。
- [ ] 說得出你最後留下的 index 為什麼比其他試過的好。
- [ ] 收尾後 `SELECT COUNT(*) FROM todos;` 回到灌資料前的數字，`\di` 看不到你建的 index。

任務 3
- [ ] 標籤表有 **4 列**（緊急、工作、程式、長期），沒有重複。
- [ ] todo 表有 **3 列**（寫專案週報、修登入頁的 bug、學會 SQL JOIN）。
- [ ] 中介表有 **7 列**。
- [ ] JOIN 拼回來的結果是 **7 列**，每一列的 (標題, 標籤) 都能在 `practice_todo_tags_flat` 找到。
- [ ] 對中介表重複插入同一組 (todo, 標籤) 會得到 ERROR。

> 三個任務都打勾，代表你不只會照著工作坊打指令，還能自己判斷什麼時候要交易、index 該建在哪、資料該怎麼拆。下一堂 [第 11 堂](../11-prisma-basics/) 換 Prisma 上場。
