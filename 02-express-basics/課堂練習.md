# 課堂練習：把 REST 模式套到一個全新資源

> 這不是工作坊的延伸，而是**把這章的核心重點再走一遍**——但這次沒有逐步指引，你得自己寫。
>
> 核心重點：路由對應 HTTP 方法、輸入驗證、回正確的狀態碼、找不到回 404。

工作坊帶你做完 `/todos`。現在你要在**同一支 `app.js`** 裡，自己長出一個全新的記憶體資源 `/notes`（隨手筆記），把同一套模式親手寫一次。

---

## 任務

在 `/todos` 的程式碼下面，加上 `notes` 的記憶體陣列與五個路由。

**資料形狀**（每筆 note）：

```js
{ id: 1, text: '記得買牛奶', pinned: false, createdAt: '2026-...' }
```

**要做出的五個路由**：

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/notes` | 回傳全部 notes |
| GET | `/notes/:id` | 回傳單筆；找不到回 404 |
| POST | `/notes` | 新增一筆 note |
| PATCH | `/notes/:id` | 更新 `text` 或切換 `pinned` |
| DELETE | `/notes/:id` | 刪除一筆 |

**明確規格**（這幾條就是這章重點，別漏）：

- 新增成功回 **201**，不是 200。
- 新增時若 `text` 缺少或是空字串，回 **400** 加一段 JSON 錯誤訊息。
- `PATCH` 時 `pinned` 若不是布林值，回 **400**。
- 任何 `:id` 找不到，回 **404**。
- 刪除成功回 **204**（沒有 body）。
- `id` 用一個遞增的 `nextNoteId`，**不要**用 `notes.length + 1`。

> 💡 卡在「為什麼是這個狀態碼」時，回去翻 [概念卡：HTTP 狀態碼](../concepts/http-狀態碼.md)。不要翻 `/todos` 的程式碼照抄——憑記憶寫，寫不出來才回去看，這樣才練得到。

## 自我檢核

把伺服器跑起來，用下面的 curl（或 REST Client / Postman）逐條打，對照預期結果。**全過才算完成**：

```bash
# 1. 新增一筆 → 應回 201，body 是剛建立的 note
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{"text":"記得買牛奶"}'

# 2. 缺 text → 應回 400
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{}'

# 3. 列出全部 → 應回 200 + 陣列
curl -i http://localhost:3000/notes

# 4. 切換 pinned → 應回 200，pinned 變 true
curl -i -X PATCH http://localhost:3000/notes/1 -H "Content-Type: application/json" -d '{"pinned":true}'

# 5. pinned 給字串 → 應回 400
curl -i -X PATCH http://localhost:3000/notes/1 -H "Content-Type: application/json" -d '{"pinned":"yes"}'

# 6. 刪一筆不存在的 → 應回 404
curl -i -X DELETE http://localhost:3000/notes/999
```

- [ ] 1. 新增成功是 `201`（不是 200）
- [ ] 2. 缺 `text` 回 `400` 且有 JSON 錯誤訊息
- [ ] 3. 列表回 `200` 且是陣列
- [ ] 4. `PATCH` 切 `pinned` 成功
- [ ] 5. `pinned` 型別錯回 `400`
- [ ] 6. 刪不存在的回 `404`

> 六條全綠，代表你已經能獨立套用這章的 REST 模式，不只是跟著工作坊抄。
