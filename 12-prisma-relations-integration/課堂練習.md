# 課堂練習：依標籤篩選、統計每個清單

> 這不是工作坊的延伸，而是**把這堂的核心重點再走一遍**，但這次沒有逐步指引，你得自己寫。
>
> 核心重點：在關聯上下查詢條件；用 `include` / `select` 決定要帶出哪些關聯資料；驗證寫在 service。

這個練習**不用 AI**。

---

## 任務

**1. 依標籤篩選 todo**

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/todos?tag=急件` | 只回傳**有貼「急件」標籤**的 todo |

- 可以跟既有的 `?completed=` 一起用：`/todos?tag=急件&completed=false`。
- 標籤名稱不存在時，回傳空陣列（200），不是 404。

**2. 每個清單有幾筆 todo**

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/lists` | 每個清單多一個 `todoCount` 欄位，和一個 `doneCount`（已完成幾筆） |

回應形狀：

```json
[
  { "id": 1, "name": "工作", "todoCount": 3, "doneCount": 1 }
]
```

**明確規格**（這幾條就是這堂重點，別漏）：

- 第 1 題的篩選要在**資料庫查詢**裡完成（Prisma 的 `where`），不准撈出全部 todo 再用 JavaScript `filter`。
- 第 2 題的回應**不准**包含每筆 todo 的完整內容，只要數字。
- 所有邏輯寫在 service；controller 最多多傳一個 query 參數。
- 不准修改 `schema.prisma`。

> 💡 第 1 題：查查 Prisma 文件的「relation filters」，關鍵字是 `some`。第 2 題：可以用 `_count`，也可以想想 `doneCount` 有沒有別的做法。不要翻完成版照抄：先自己寫，寫不出來才回去查。

## 自我檢核

先準備資料：建兩個清單、幾筆 todo、兩個標籤（「急件」「家裡」），貼上一些標籤、把幾筆 todo 標成完成。

```bash
curl "http://localhost:3000/todos?tag=急件"
curl "http://localhost:3000/todos?tag=急件&completed=false"
curl "http://localhost:3000/todos?tag=不存在的標籤"
curl http://localhost:3000/lists
```

- [ ] 1. `?tag=急件` 只回傳有這個標籤的 todo，回應裡照樣帶 `list` 和 `tags`
- [ ] 2. `?tag=` 和 `?completed=` 可以一起用
- [ ] 3. 不存在的標籤回 `200` 和空陣列
- [ ] 4. `GET /lists` 每個清單都有正確的 `todoCount` 和 `doneCount`，沒有 todo 的完整內容
- [ ] 5. 篩選是在 Prisma 的 `where` 裡做的，service 裡沒有對 todo 陣列 `filter`
