# 課堂練習：自己長出一組新的 M:N 關聯

> 這不是工作坊的延伸，而是**把這章的核心重點再走一遍**——但這次沒有逐步指引，你得自己定義關聯、自己用 `with` 撈出來。
>
> 核心重點：新增一張中介表（M:N）、用 `relations()` 把表連起來、查詢時用 `with` 把關聯帶出來。

工作坊帶你做完了「todo 貼標籤（M:N）」。現在你要在**同一份 schema** 裡，自己再長出一組**全新的 M:N 關聯**：清單可以指派多個「成員」（members），一個成員也可以參與多個清單。整套——表、`relations()`、查詢——都得你自己寫。

> ⚠️ 這跟 README 的挑戰題（`/lists/:id/todos`、`?tag=`、`/stats`）不一樣，那幾題碰的都是既有關聯；這題要你**從零定義一組新的多對多**。

---

## 任務

### 1. 擴充 schema（`src/db/schema.js`）

- 新增 `members` 表：`id`、`name`（必填）。
- 新增中介表 `listMembers`：連 `lists` 與 `members`，用**複合主鍵**`(listId, memberId)`，兩個外鍵都 `onDelete: 'cascade'`。
- 補上 `relations()`：讓 `lists` 能帶出它的 members、`members` 能帶出它參與的 lists（**雙向都要查得到**）。
- 產生並套用 migration（`npm run generate` / `npm run migrate`）。

### 2. 路由

| 方法 | 路徑 | 行為 |
|---|---|---|
| POST | `/members` | 建立成員；`name` 缺或空字串回 **400** |
| POST | `/lists/:id/members` | 把某成員加進某清單；body `{ "memberId": n }` |
| GET | `/lists/:id` | 回傳單一清單，**並用 `with` 帶出它的 `members` 陣列** |

**明確規格**（這幾條就是這章重點，別漏）：

- `POST /lists/:id/members` 要先確認 list 與 member 都存在，任一不存在回 **404**。
- 同一個成員重複加進同一清單**不該爆掉**（中介表複合主鍵會擋；想想 `onConflictDoNothing`）。
- `GET /lists/:id` 回傳的 `members` 必須是**乾淨的成員物件陣列**（`[{ id, name }]`），不是中介表的列。找不到清單回 **404**。

> 💡 卡在「relations() 怎麼穿過中介表」時，回去翻 [概念卡：Drizzle 的關聯查詢](../concepts/drizzle-關聯查詢.md)。不要翻工作坊的 `todoTags` 程式碼照抄——憑記憶寫，寫不出來才回去看，這樣才練得到。

## 自我檢核

把伺服器跑起來，用下面的 curl（或 REST Client / Postman）逐條打，**重點看回傳結構裡關聯有沒有被 `with` 帶出來**。**全過才算完成**：

```bash
# 1. 建一個清單與兩個成員
curl -s -X POST localhost:3000/lists   -H 'Content-Type: application/json' -d '{"name":"專案A"}'
curl -s -X POST localhost:3000/members -H 'Content-Type: application/json' -d '{"name":"小明"}'
curl -s -X POST localhost:3000/members -H 'Content-Type: application/json' -d '{"name":"小華"}'

# 2. 成員缺 name → 應回 400
curl -i -X POST localhost:3000/members -H 'Content-Type: application/json' -d '{}'

# 3. 把兩個成員都加進清單 1 → 應回 201
curl -i -X POST localhost:3000/lists/1/members -H 'Content-Type: application/json' -d '{"memberId":1}'
curl -i -X POST localhost:3000/lists/1/members -H 'Content-Type: application/json' -d '{"memberId":2}'

# 4. 重複加同一人 → 不該 500（再打一次 memberId:1）
curl -i -X POST localhost:3000/lists/1/members -H 'Content-Type: application/json' -d '{"memberId":1}'

# 5. 加進不存在的清單 → 應回 404
curl -i -X POST localhost:3000/lists/999/members -H 'Content-Type: application/json' -d '{"memberId":1}'

# 6. 查清單 1 → 回傳應帶 members 陣列，且是乾淨的 [{id,name}]
curl -s localhost:3000/lists/1
```

- [ ] 1. 清單與成員都建得起來
- [ ] 2. 成員缺 `name` 回 `400`
- [ ] 3. 把成員加進清單成功（`201`）
- [ ] 4. 重複加同一人**不會** `500`
- [ ] 5. 清單或成員不存在回 `404`
- [ ] 6. `GET /lists/1` 的回傳裡有 `members` 陣列，且每筆是 `{ id, name }`（**不是**中介表的 `{ listId, memberId }`）

> 六條全綠——尤其第 6 條看到關聯被 `with` 乾淨帶出——代表你已經能獨立設計並查詢一組新的 M:N 關聯，不只是跟著工作坊抄。
