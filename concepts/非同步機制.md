# 概念卡：Node.js 的非同步機制

> 一句話：Node 是**單執行緒**的，碰到「要等」的事（讀檔、查資料庫、打 API）不會卡住整支程式——它把工作交出去、繼續做別的，事情好了再回來處理結果。這就是非同步。

---

## 一、為什麼要非同步？

Node 只有一條主執行緒。如果讀檔案時「同步」地站在那邊等，這段時間整個伺服器都不能處理其他請求——一個人卡住，全部排隊。

```js
// 同步：readFileSync 會卡住主執行緒直到讀完
const data = fs.readFileSync('big.txt', 'utf8')
console.log('要等上面讀完，這行才會跑')
```

非同步則是「發出請求後就先走」，所以同時讀兩個檔案幾乎跟讀一個一樣快：

```js
const p1 = fs.readFile('a.txt', 'utf8')   // 發出去，不等
const p2 = fs.readFile('b.txt', 'utf8')   // 也發出去
console.log('檔案還在讀，我已經執行到這行了')
await Promise.all([p1, p2])               // 兩個一起等
```

> 心智模型：同步像在櫃台排隊一個一個辦；非同步像抽號碼牌，辦事員同時處理很多人，叫到號再回來。

---

## 二、三個世代的寫法

非同步的「結果晚點才到」，怎麼接？歷史上有三種寫法，新舊都要認得：

### 1. Callback（最早，會「巢狀地獄」）

```js
fs.readFile('a.txt', 'utf8', (err, data) => {
  if (err) return console.error(err)   // 錯誤從第一個參數傳回來
  console.log(data)
})
```

巢狀多了就是著名的 callback hell（一層包一層、向右長）。

### 2. Promise（用 `.then()` 串起來）

```js
fs.promises.readFile('a.txt', 'utf8')
  .then(data => console.log(data))
  .catch(err => console.error(err))
```

Promise 把「成功 / 失敗」變成可以串接的物件，攤平了巢狀。

### 3. async / await（現代，本課程主力）

```js
async function read() {
  try {
    const data = await fs.promises.readFile('a.txt', 'utf8')
    console.log(data)
  } catch (err) {
    console.error(err)   // 非同步錯誤用 try/catch 接
  }
}
```

`await` 讓非同步程式碼**讀起來像同步**，但實際上不卡執行緒。這是現在的標準寫法。

---

## 三、三個關鍵觀念

1. **`await` 只能在 `async` function 裡用**（或檔案最上層的 top-level await）。
2. **非同步的錯誤要對應地接**：callback 看第一個 `err` 參數、Promise 用 `.catch()`、async/await 用 `try/catch`。漏接就會變成 unhandled rejection。
3. **要「同時做」就別逐個 `await`**：

```js
// 慢：一個做完才做下一個（總時間 = 相加）
const a = await readFile('a.txt')
const b = await readFile('b.txt')

// 快：一起發出，一起等（總時間 = 最慢那個）
const [a, b] = await Promise.all([readFile('a.txt'), readFile('b.txt')])
```

## 延伸
- 之後每一堂的請求處理、資料庫查詢，全都是 async/await。先在這裡把它弄熟，後面就順。
- Node 能單執行緒還撐住高併發，靠的是底層的 **event loop（事件迴圈）**：等的時候執行緒被釋放去做別的，事情好了回呼函式再排進佇列。執行順序（同步 → microtask → timer）在[第 2 堂工作坊](../02-async-and-event-loop/工作坊.md)的步驟 3 有實際範例。
