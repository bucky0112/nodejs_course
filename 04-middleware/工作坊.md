# 第 4 堂工作坊：把 middleware 串進 todo app

上一堂照抄了一行 `app.use(express.json())`。這一堂要搞懂它到底是什麼，並且寫自己的 middleware、裝第三方的 middleware，最後用 middleware 處理「找不到路徑」。

>

## 步驟 0：middleware 是什麼

middleware 是一串「**夾在請求進來、回應送出之間**」依序執行的函式。每個都長這樣：

```js
(req, res, next) => {
  // 可以讀寫 req、res
  next() // 交給下一個；不呼叫，請求就停在這裡
}
```

`app.use(...)` 的順序，就是執行順序。路由的 handler 其實也是 middleware，只是有條件（方法和路徑對了才跑）。

> 🧠 完整說明 → [概念卡：Express Middleware](../concepts/express-middleware.md)

## 步驟 1：內建 middleware，拿掉看看會怎樣

先把 `app.use(express.json())` 註解掉，存檔，再新增一筆 todo：

```bash
curl -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"買牛奶"}'
```

伺服器會出錯：`req.body` 是 `undefined`，`const { title } = req.body` 就炸了。**Express 預設不會解析請求主體**，要靠 `express.json()` 這個內建 middleware 讀出 JSON、放進 `req.body`。

把註解拿掉，恢復原狀。

> ✅ **檢查點 A**：說得出拿掉 `express.json()` 後 `req.body` 會變成什麼、為什麼。

---

## 步驟 2：自訂 middleware，記錄每個請求

開發時想知道「進來了哪些請求、花多久」。在 `app.use(express.json())` 後面加：

```js
app.use((req, res, next) => {
  const start = Date.now()
  res.on('finish', () => {
    console.log(`${req.method} ${req.originalUrl} → ${res.statusCode} (${Date.now() - start}ms)`)
  })
  next()
})
```

打幾次 API，終端機每次都會印出一行記錄。

試試看：把 `next()` 那一行刪掉，再打一次 API，會發生什麼事？（請求會一直轉圈圈，因為沒人把棒子交下去。）試完記得加回來。

> ✅ **檢查點 B**：每個請求都印出一行記錄；說得出刪掉 `next()` 為什麼會卡住。

---

## 步驟 3：第三方 middleware，用 morgan 取代手寫

「記錄請求」這件事太常見了，已經有人寫好套件：

```bash
npm install morgan
```

把步驟 2 手寫的 logger **整段刪掉**，換成：

```js
import morgan from 'morgan'

// 放在 app.use(express.json()) 後面
app.use(morgan('dev'))
```

再打幾次 API，終端機會印出有顏色的記錄，例如 `POST /todos 201 2.554 ms - 85`。

第三方 middleware 的用法都一樣：`npm install`、`import`、`app.use(...)`。

> ✅ **檢查點 C**：手寫 logger 已刪除，morgan 正常印出記錄。

## 步驟 4：路由層級 middleware，把驗證抽出來

目前 `POST /todos` 的 handler 裡混著「驗證 title」和「新增 todo」兩件事。把驗證抽成一個 middleware：

```js
const validateTitle = (req, res, next) => {
  const { title } = req.body ?? {}
  if (typeof title !== 'string' || title.trim() === '') {
    return res.status(400).json({ error: 'title 必填，且必須是非空字串' })
  }
  next()
}
```

> 💡 `req.body ?? {}`：請求沒有 JSON 主體時，`req.body` 是 `undefined`，先給一個空物件，解構才不會炸。

然後**掛在路由上**，而不是 `app.use`：

```js
app.post('/todos', validateTitle, (req, res) => {
  const todo = {
    id: nextId++,
    title: req.body.title.trim(),
    completed: false,
    createdAt: new Date().toISOString(),
  }
  todos.push(todo)
  res.status(201).json(todo)
})
```

`validateTitle` 只對 `POST /todos` 生效。驗證不過就直接回 400、不呼叫 `next()`，handler 根本不會執行；通過了才交給 handler。

> ✅ **檢查點 D**：新增時缺 title 回 400，而且 handler 裡已經沒有驗證的程式碼。

## 步驟 5：順序很重要，用 middleware 接住「找不到路徑」

打一個不存在的路徑：

```bash
curl -i http://localhost:3000/not-exist
```

Express 預設回一段 HTML。我們的 API 應該一律回 JSON。在**所有路由的最後面**加：

```js
app.use((req, res) => {
  res.status(404).json({ error: `找不到路徑 ${req.method} ${req.originalUrl}` })
})
```

為什麼一定要放最後？因為 middleware 由上往下跑。這段沒有檢查路徑、誰來都接，放在最前面的話，所有請求都會被它攔下回 404。放在最後，代表「前面的路由都沒人接，才輪到我」。

試試看：把這段移到所有路由**前面**，再打 `GET /todos`，看看結果。試完移回去。

> ✅ **檢查點 E（完成版）**：亂打路徑回 404 JSON，正常路由不受影響。你的 `app.js` 應該跟 [`完成版/app.js`](./完成版/app.js) 一致。
