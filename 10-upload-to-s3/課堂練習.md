# 課堂練習：自己長出一條「私有檔案」上傳/取回

> 這不是工作坊的延伸，而是**把這章的核心重點再走一遍**——但這次沒有逐步指引，你得自己寫。
>
> 核心重點：用 multer 接 multipart 檔案、存進私有 S3 bucket、再用 **presigned URL** 做暫時性的私有讀取。

工作坊帶你做完會員頭像 `/me/avatar`。現在你要在**同一支 `app.js`** 裡，自己長出一個全新資源 `/me/files`（會員的私人附件，例如收據、PDF），把同一套「上傳 → 存私有 S3 → presigned URL 取回」的模式親手寫一次。

> **這次請不要翻完成版**——憑理解自己寫一遍，才知道哪裡其實沒搞懂。卡住了再回去翻，但先別照抄。

## 任務

在 `/me/avatar` 的程式碼下面，加上 `/me/files` 的上傳與取回路由。沿用工作坊已經設好的 `s3`、`BUCKET`、`requireAuth`。

**要做出的兩個路由**：

| 方法 | 路徑 | 行為 |
|---|---|---|
| POST | `/me/files` | 接一個檔案（欄位名 `file`），存到私有 S3，回 `{ key }` |
| GET | `/me/files?key=...` | 對該 key 簽一個短期 presigned URL，回 `{ url }` |

**明確規格**（這幾條就是這章重點，別漏）：

- 兩條路由都要掛 `requireAuth`，**未登入回 401**。
- 沒帶檔案（`req.file` 為空）回 **400**。
- multer 要設 **大小上限**（自己定，例如 5MB）；超過要回 **413**（在錯誤處理 middleware 接 `LIMIT_FILE_SIZE`）。
- object key **不要信任使用者原始檔名**——自己用隨機值組 key，並把 key 放在 `files/<userId>/` 底下。
- presigned URL 的 `expiresIn` 自己設一個**短**的秒數（例如 120 秒），不要簽很長。
- bucket 全程保持**私有**（封鎖公開存取），取回一律走 presigned URL，**不要**改成公開網址。

> 💡 卡在「為什麼要 presigned URL、為什麼 key 不能用原始檔名」時，回去翻 [概念卡：S3 與 Presigned URL](../concepts/s3-presigned-url.md) 與 [概念卡：用 multer 處理檔案上傳](../concepts/檔案上傳-multer.md)。不要翻 `/me/avatar` 的程式碼照抄——憑記憶寫，寫不出來才回去看，這樣才練得到。

## 觀念題（用文字作答）

1. 工作坊把 bucket 設成私有、靠後端簽 presigned URL 取回。如果改成「把 bucket 開公開、直接給 `https://bucket.s3.../key` 當網址」，**會多出哪些風險**？（提示：誰能存取、能不能列舉別人的檔案、權限怎麼收回。）
2. presigned URL 設 `expiresIn: 120`，過期後再用同一條 URL 會發生什麼？這個「**過期**」對安全有什麼意義？如果簽成 `expiresIn: 604800`（七天），又有什麼壞處？

## 自我檢核

先登入拿一個 token，再逐條打。準備一張小圖或小檔當測試檔。**全過才算完成**：

```bash
# 取得 token（換成你的帳密）
curl -s -X POST http://localhost:3000/auth/login -H "Content-Type: application/json" -d '{"username":"alice","password":"secret123"}'

# A. 未登入上傳 → 應回 401
curl -i -X POST http://localhost:3000/me/files -F "file=@./test.png"

# B. 帶 token、不帶檔 → 應回 400
curl -i -X POST http://localhost:3000/me/files -H "Authorization: Bearer <貼上 token>"

# C. 帶 token、上傳一個檔 → 應回 201（或 200），body 有 key
curl -i -X POST http://localhost:3000/me/files -H "Authorization: Bearer <貼上 token>" -F "file=@./test.png"

# D. 拿上一步的 key 換 presigned URL → 應回 {url}
curl -s "http://localhost:3000/me/files?key=<貼上剛剛的 key>" -H "Authorization: Bearer <貼上 token>"

# E. 直接用上一步的 url 下載檔案 → 應能取得內容（200）
curl -i "<貼上 presigned url>"

# F.（過期觀念）等過了你設的 expiresIn 秒數後，再打同一條 url → 應被拒（403）
curl -i "<同一條 presigned url，等過期後>"
```

- [ ] A. 未登入上傳回 `401`
- [ ] B. 不帶檔回 `400`
- [ ] C. 合法上傳回 `201`/`200`，body 有 `key`，且 key **不是**原始檔名
- [ ] D. 拿 key 能換到一條 presigned `url`
- [ ] E. 用該 url 能直接取得檔案內容（`200`）
- [ ] F. 過了 `expiresIn` 後同一條 url 被拒（`403`），證明 URL 真的會過期
- [ ] 觀念題 1、2 你寫得出「公開 bucket 的風險」與「presigned URL 過期的意義」

> 全綠 + 答得出兩題觀念題，代表你抓到了這章最核心的一點：私有 bucket + 短期 presigned URL，是怎麼做到「能讀、但只能暫時讀、且收得回」的。
