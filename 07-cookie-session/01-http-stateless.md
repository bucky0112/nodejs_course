# HTTP 的無狀態問題

## 什麼是「無狀態」？

HTTP 協定是 **無狀態（Stateless）** 的，意思是：

> 每一次請求都是獨立的，伺服器不會記得上一次請求的任何資訊。

這就像你每次去便利商店，店員都不認識你一樣。

```
第一次請求：「我要登入」    → 伺服器：「好，登入成功！」
第二次請求：「給我我的訂單」 → 伺服器：「你是誰？」
```

## 為什麼要設計成無狀態？

1. **簡單** - 伺服器不用追蹤每個用戶的狀態
2. **可擴展** - 任何一台伺服器都能處理任何請求（適合負載平衡）
3. **可靠** - 請求失敗時，重新發送即可，不用擔心狀態不一致

## 無狀態帶來的問題

但是，很多功能需要「記住」用戶：

| 場景 | 需要記住什麼 |
|------|------------|
| 購物車 | 用戶加了哪些商品 |
| 登入狀態 | 用戶是否已經登入、是誰 |
| 語言偏好 | 用戶選擇的語言 |
| 瀏覽紀錄 | 用戶看過哪些商品 |

## 解決方案：讓瀏覽器幫忙記

既然伺服器不記得，那就讓 **瀏覽器** 來記！

```
┌─────────────┐                      ┌─────────────┐
│   瀏覽器    │  ── 請求 + 識別碼 ──▶ │   伺服器    │
│             │                      │             │
│  儲存識別碼  │ ◀── 回應 + 識別碼 ── │  查詢識別碼  │
└─────────────┘                      └─────────────┘
```

這個「識別碼」就是我們接下來要學的 **Cookie**！
