# 課堂練習：讀懂部署失敗，自己把它修好

> 這章是操作章，重點不在「再寫一段 code」，而在**看懂上線後為什麼壞掉**——環境變數本機與正式的差別、port 要聽平台的、migration 有沒有在部署時自動跑。
>
> 工作坊帶你照著步驟部署成功。但真實上線最常遇到的是**部署失敗**——log 一堆紅字、curl 打不通。這個練習給你四個壞掉的情境，你要當「值班工程師」：**判斷哪裡錯、寫出正確的設定或指令**。

---

## 怎麼作答

每一題請寫下兩件事：

1. **病因**：哪個環節錯了？（一兩句，講清楚「為什麼這會讓部署失敗」）
2. **修法**：要改哪個檔 / 哪個設定，改成什麼？（貼出正確的那一行或那一段）

> 🧠 卡住時回去翻 [概念卡：部署——環境變數與正式設定](../concepts/部署-環境變數與正式設定.md)，但先別翻工作坊的 `railway.json` 照抄——憑理解判斷，這樣才練得到「看 log 抓問題」的能力。

---

## 情境 1：部署成功，但網址打不通

部署 log 顯示伺服器有啟動，印出 `Server listening on port 3000`。但 Railway 給的公開網址怎麼打都連不上（502 / Application failed to respond）。

你的 `app.js` 結尾是：

```js
app.listen(3000, () => {
  console.log('Server listening on port 3000')
})
```

- 病因是什麼？
- `app.listen` 那行該怎麼寫？

---

## 情境 2：啟動就 crash，log 出現連線錯誤

部署後服務一直重啟，log 反覆出現：

```
Error: connect ECONNREFUSED 127.0.0.1:5432
```

你檢查 Railway 的 Postgres 確實有開、也健康。但你的服務 **Variables 分頁是空的**，一個變數都沒設。

- 病因是什麼？（為什麼會去連 `127.0.0.1:5432`？）
- 在 Railway 的 Variables 要設哪個變數、值要怎麼填（讓它指向同專案的 Postgres）？

---

## 情境 3：app 起得來，但一註冊就 500

服務有啟動、首頁也回得了，但只要打 `POST /auth/register`，就回 500，log 裡是：

```
error: relation "users" does not exist
```

你的 `package.json` 有 `"migrate": "drizzle-kit migrate"`，本機跑過也沒問題。但你的專案根目錄**沒有 `railway.json`**，部署只是單純 `npm start`。

- 病因是什麼？（資料表為什麼不存在？）
- 要補一個 `railway.json`，把 migration 接到部署流程。請寫出完整內容（builder 用 Nixpacks）。

---

## 情境 4：祕密外洩的隱患

某同學為了「省事」，把 `JWT_SECRET` 直接寫死在程式碼裡：

```js
const SECRET = 'my-super-secret-key-123'
```

而且他的 `.gitignore` 裡**沒有** `.env`，整個 repo 推上 GitHub 了。

- 這裡有**兩個**問題，分別是什麼？
- 正確做法是什麼？（祕密該放哪、`.gitignore` 該補什麼、程式裡該怎麼讀這個值）

---

## 自我檢核

把你的修法實際套到自己的 todo app，重新部署，然後逐項確認。**全綠才算把這章學起來**：

```bash
# 換成你自己的 Railway 網址。先註冊拿 token
curl -i -X POST https://你的app.up.railway.app/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"secret123"}'

# 用拿到的 token 打受保護的 /todos
curl -i https://你的app.up.railway.app/todos \
  -H 'Authorization: Bearer <貼上 token>'
```

**可觀察的檢核點：**

- [ ] 線上網址 `curl` 註冊 → 回 `201`（不是 502、不是 500）
- [ ] 線上登入後帶 token 打 `/todos` → 回 `200`
- [ ] 部署 log 裡看得到 `npm run migrate`（或 `drizzle-kit migrate`）有跑過
- [ ] Railway 的 Variables 裡有 `DATABASE_URL`、`JWT_SECRET`，**程式碼裡找不到**任何寫死的祕密
- [ ] `git` 追蹤的檔案中**沒有** `.env`（`git ls-files | grep .env` 應該只看到 `.env.example`）

**觀念自評（寫得出來才算懂）：**

- [ ] 我能說清楚「為什麼正式環境不能寫死 port，要讀 `process.env.PORT`」
- [ ] 我能說清楚「為什麼 `DATABASE_URL` 要在平台設、而不是寫在程式裡」
- [ ] 我能說清楚「migration 為什麼要在部署時自動跑，而不是只在本機跑過」

> 四題都答得出病因+修法、五個檢核點全綠，代表你不只是「跟著工作坊按一次成功」，而是真的會自己 debug 一次部署。
