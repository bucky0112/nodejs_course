# 工作坊：把 todo app 裝進 Docker

這一章我們不改 todo app 的程式，而是幫它「打包環境」——讓任何裝了 Docker 的機器，都能用一行指令把 app + 資料庫一起跑起來，跑出來的環境完全一致。

> 從 [M2] 的 todo app 開始（Express + Drizzle + PostgreSQL）。手邊沒有的話，可以直接複製 [`完成版/`](./完成版/) 的 `app.js`、`src/`、`drizzle.config.js`、`package.json`。
>
> 卡住了？每個檢查點都對得上 [`完成版/`](./完成版/) 裡的檔案。

---

## 步驟 1：寫 Dockerfile，把 app 包成 image

`Dockerfile` 是 build image 的「食譜」。在專案根目錄建立：

```dockerfile
# 基底映像：slim 版比完整版小很多
FROM node:22-slim

WORKDIR /app

# 先只複製 package 檔，單獨裝套件 —— 利用 Docker 的層快取
COPY package*.json ./
RUN npm ci --omit=dev

# 再複製其餘程式碼
COPY . .

ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "app.js"]
```

**為什麼要分兩次 COPY？** Dockerfile 每個指令是一「層」，會被快取。把「裝套件」和「複製程式碼」分開，只要 `package.json` 沒變，改程式碼時就不必重裝套件——build 快非常多。

> 🧠 image / container / layer / volume 是什麼 → [概念卡：Docker image vs container](../concepts/docker-image-vs-container.md)

> ✅ **檢查點 A**：`Dockerfile` 存在，且 `FROM node:22-slim`（不是舊的 node:20）。

---

## 步驟 2：用 `.dockerignore` 瘦身

build 時 Docker 會把整個資料夾打包成「build context」送給引擎。`node_modules`、`.env`、`.git` 不該進去（拖慢 build、甚至洩漏祕密）。建立 `.dockerignore`：

```
node_modules
.env
.git
.gitignore
drizzle
Dockerfile
compose.yaml
.dockerignore
```

> 💡 跟 `.gitignore` 同樣的概念，只是這次擋的是「進 image 的東西」。

> ✅ **檢查點 B**：`.dockerignore` 至少擋掉 `node_modules` 和 `.env`。

---

## 步驟 3：寫 compose.yaml，app + db 一起跑

光有 app 還不夠——它要連 PostgreSQL。手動 `docker run` 兩個容器再接網路很麻煩，**Docker Compose** 讓你用一個檔案定義全部。建立 `compose.yaml`：

```yaml
# 注意：新版 Compose 不需要 version: 欄位（寫了會跳警告）
name: todo-app

services:
  app:
    build: .
    ports:
      - '3000:3000'
    environment:
      NODE_ENV: production
      PORT: 3000
      # 主機名稱是另一個 service 的名字「db」，不是 localhost！
      DATABASE_URL: postgresql://todo:todo_pw@db:5432/todo_app
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: todo
      POSTGRES_PASSWORD: todo_pw
      POSTGRES_DB: todo_app
    ports:
      - '5433:5432' # 對外用 5433，避免撞到本機 PostgreSQL
    volumes:
      - todo_pgdata:/var/lib/postgresql/data # 資料存到 volume，容器刪了也不掉
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U todo -d todo_app']
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  todo_pgdata:
```

三個關鍵：

1. **`DATABASE_URL` 裡的主機是 `db`**，不是 `localhost`。Compose 會幫同一網路裡的 service 做 DNS 解析——app 容器裡的「db」就指向資料庫容器。
2. **`depends_on` + `condition: service_healthy`**：等資料庫 `pg_isready` 通過，才啟動 app，避免 app 搶先連線失敗。
3. **`volumes`**：資料庫資料寫進 `todo_pgdata` 這個 volume（容器外）。容器刪掉重建，資料還在。

> ⚠️ 舊教材常在開頭寫 `version: '3.8'`——這在新版 Compose 已經**過時、會跳警告**，直接刪掉。

> ✅ **檢查點 C**：`docker compose config` 不報錯（驗證 YAML 正確）。

---

## 步驟 4：跑起來、建表、測 API

```bash
# build image 並拉起 app + db 兩個容器（-d 背景執行）
docker compose up -d --build

# 看狀態：兩個都該是 running / healthy
docker compose ps

# 第一次要建表：在 app 容器裡跑 migration
docker compose exec app npm run migrate
```

> 💡 為什麼 migration 要 `docker compose exec app ...`？因為要在**容器內**對**容器網路裡的 db** 連線。在你本機直接跑 `npm run migrate` 會連不到（除非改用對外的 5433 埠）。

測 API：

```bash
curl localhost:3000/health
curl -X POST localhost:3000/todos -H 'Content-Type: application/json' -d '{"title":"用 Docker 跑起來"}'
curl localhost:3000/todos
```

看日誌、收工：

```bash
docker compose logs -f app    # 追 app 日誌（Ctrl+C 離開）
docker compose down           # 停掉並移除容器（volume 裡的資料還在）
```

> ✅ **檢查點 D（完成版）**：`curl localhost:3000/todos` 回傳剛新增的 todo；`down` 再 `up` 後資料還在。
