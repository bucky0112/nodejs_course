# 課堂練習：把同一件事用 callback → Promise → async/await 各寫一遍

> 這不是工作坊的延伸，而是**把這堂的核心重點再走一遍**——但這次沒有逐步指引，你得自己寫。
>
> 核心重點：非同步的三代寫法（callback → Promise → async/await）其實在做同一件事，差別只在「怎麼接住結果、怎麼把多步驟串起來」。會手寫一遍，才真的懂 `async/await` 底下藏的是什麼。

工作坊用 `fs` 讓你**看到**非同步的順序。現在你要自己造一個「會等一下才完成的工作」，把同一段流程用三種寫法各寫一次，親手感受它們的差異。

---

## 任務

新建一支 `delay-practice.js`。先寫一個「假裝在忙」的延遲函式當素材：

```js
// 這個給你當起點，模擬「要等 ms 毫秒才拿得到資料」的非同步工作
function fetchData(label, ms) {
  // ⚠️ 接下來三種寫法都圍繞這個概念，但實作方式不同，請自己決定它要長怎樣
}
```

然後完成下面三題。**三題要做的事一模一樣**：依序「拿到 A」→「拿到 B」→ 印出 `A + B 都拿到了`，每步之間各等一小段時間。

**題目 1 — callback 版**
- 用 `setTimeout` 實作 `fetchDataCb(label, ms, callback)`，等待後用 `callback(null, 結果)` 把資料交出去。
- 先拿 A，**在 A 的 callback 裡**再拿 B，**在 B 的 callback 裡**印出完成。
- 你會親手寫出傳說中的巢狀縮排（callback hell 的雛形）。

**題目 2 — Promise 版**
- 把延遲工作包成回傳 `Promise` 的 `fetchDataPromise(label, ms)`（內部用 `setTimeout` + `resolve`）。
- 用 `.then()` 鏈把「拿 A → 拿 B → 印出完成」串起來。
- 加一個 `.catch()`。

**題目 3 — async/await 版**
- 重用題目 2 的 `fetchDataPromise`。
- 寫一個 `async function run()`，用 `await` 依序拿 A、拿 B，再印出完成。
- 用 `try/catch` 接錯誤。

**明確規格**（這幾條就是這堂重點，別漏）：

- 三題的**輸出順序與內容要一致**：先 A、再 B、最後一行 `A + B 都拿到了`。
- 三題都要能單獨從同一支檔案跑出來（可以在檔尾依序呼叫，用 `console.log` 標好是哪一題）。
- callback 版**一定要有巢狀**（B 寫在 A 的 callback 裡），不准偷偷改成 Promise。
- async/await 版**不准**再出現 `.then()`——全部用 `await`。
- 三個版本都要處理「失敗」情境（callback 的 `err` 參數、Promise 的 `.catch`、async 的 `try/catch`）。

> 💡 卡在「Promise 到底 resolve 了什麼、await 在等什麼」時，回去翻 [概念卡：Node.js 的非同步機制](../concepts/非同步機制.md)。不要翻工作坊的 `three-ways.js` 照抄——憑記憶寫，寫不出來才回去看，這樣才練得到。

## 進階（行有餘力）

- **平行 vs 序列**：再寫一個版本，用 `Promise.all([fetchDataPromise('A', 300), fetchDataPromise('B', 300)])` 同時發兩個請求。量一下 `console.time` / `console.timeEnd`，跟「序列 await」比，總耗時差多少？想清楚為什麼。
- 想想：題目 1 如果要串到第五個資料，巢狀會深到什麼程度？這就是當年大家急著要 Promise 的原因。

## 自我檢核

把三題跑起來，對照輸出順序。**全過才算完成**：

```bash
# 跑你的練習檔，觀察印出的順序
node delay-practice.js
```

預期會看到（時間長短可自訂，重點是**順序**）：

```
[題目1 callback] 拿到 A
[題目1 callback] 拿到 B
[題目1 callback] A + B 都拿到了
[題目2 Promise] 拿到 A
[題目2 Promise] 拿到 B
[題目2 Promise] A + B 都拿到了
[題目3 async] 拿到 A
[題目3 async] 拿到 B
[題目3 async] A + B 都拿到了
```

- [ ] 1. callback 版能跑出正確順序，且 B 確實寫在 A 的 callback **巢狀**裡
- [ ] 2. Promise 版用 `.then()` 鏈串起來，且有 `.catch()`
- [ ] 3. async/await 版只用 `await`、用 `try/catch`，**沒有任何 `.then()`**
- [ ] 4. 三題的輸出順序與最後一行內容完全一致
- [ ] 5.（進階）`Promise.all` 平行版的總耗時，明顯比序列版短

> 三題寫得出來、輸出對得上，代表你真的理解 callback / Promise / async/await 是「同一件事的三種寫法」，而不只是會背 `async/await`。
