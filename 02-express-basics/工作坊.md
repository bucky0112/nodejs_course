# 工作坊：用 Express 做出 todo app 的骨架

這一章我們會從零建立一個 todo app 的後端 API。**它會一路帶到課程結束**——之後接資料庫、加會員登入、上傳頭像、部署上線，都是在今天這個骨架上長出來的。

## 步驟 0：建立專案

```bash
mkdir todo-app && cd todo-app
npm init -y
npm install express
```

打開 `package.json`，加上 `"type": "module"`（這樣才能用 `import` 語法）：

```json
{
  "name": "todo-app",
  "type": "module",
  "scripts": {
    "dev": "node --watch app.js"
  }
}
```

> 💡 `node --watch` 是 Node 18+ 內建的功能：改檔案存檔後自動重啟，不用額外裝 nodemon。

---

## 步驟 1：跑起第一個伺服器

建立 `app.js`：

```js
import express from 'express'

const app = express()
const PORT = process.env.PORT || 3000

app.get('/', (req, res) => {
  res.send('todo app 啟動成功！')
})

app.listen(PORT, () => {
  console.log(`伺服器啟動：http://localhost:${PORT}`)
})
```

執行：

```bash
npm run dev
```

打開瀏覽器到 `http://localhost:3000`，看到「todo app 啟動成功！」就對了。

> ✅ **檢查點 A**：伺服器跑得起來、首頁有回應。

## 步驟 2：讓伺服器看得懂 JSON

之後前端會用 JSON 送資料給我們。加一行內建 middleware 來解析它，並準備好存 todo 的記憶體陣列：

```js
// 放在 const app = express() 後面
app.use(express.json())

let todos = [
  { id: 1, title: '學會 Express', completed: false, createdAt: new Date().toISOString() },
]
let nextId = 2
```

> 🧠 `express.json()` 是什麼、為什麼非加不可？→ [概念卡：Express Middleware](../concepts/express-middleware.md)

## 步驟 3：讀取與新增（GET / POST）

```js
// 取得全部
app.get('/todos', (req, res) => {
  res.json(todos)
})

// 新增
app.post('/todos', (req, res) => {
  const { title } = req.body
  if (typeof title !== 'string' || title.trim() === '') {
    return res.status(400).json({ error: 'title 必填，且必須是非空字串' })
  }

  const todo = {
    id: nextId++,
    title: title.trim(),
    completed: false,
    createdAt: new Date().toISOString(),
  }
  todos.push(todo)
  res.status(201).json(todo)
})
```

兩個重點：

- **新增成功回 `201`，不是 `200`**——表示「建立了新資源」。→ [概念卡：HTTP 狀態碼](../concepts/http-狀態碼.md)
- **id 用遞增的 `nextId`，不是 `todos.length + 1`**。為什麼？因為刪掉中間幾筆後，`length + 1` 會撞到已存在的 id。

測試（用 VS Code 的 REST Client、Postman，或 curl）：

```bash
curl http://localhost:3000/todos
curl -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"買牛奶"}'
```

> ✅ **檢查點 B**：能列出 todo、能新增 todo，新增缺 title 會回 400。

## 步驟 4：單筆、更新、刪除（GET/:id、PATCH、DELETE）

```js
// 取得單筆
app.get('/todos/:id', (req, res) => {
  const id = Number(req.params.id)
  const todo = todos.find((t) => t.id === id)
  if (!todo) {
    return res.status(404).json({ error: '找不到這筆 todo' })
  }
  res.json(todo)
})

// 部分更新（PATCH：只改有送來的欄位）
app.patch('/todos/:id', (req, res) => {
  const id = Number(req.params.id)
  const todo = todos.find((t) => t.id === id)
  if (!todo) {
    return res.status(404).json({ error: '找不到這筆 todo' })
  }

  const { title, completed } = req.body
  if (title !== undefined) {
    if (typeof title !== 'string' || title.trim() === '') {
      return res.status(400).json({ error: 'title 必須是非空字串' })
    }
    todo.title = title.trim()
  }
  if (completed !== undefined) {
    if (typeof completed !== 'boolean') {
      return res.status(400).json({ error: 'completed 必須是布林值' })
    }
    todo.completed = completed
  }
  res.json(todo)
})

// 刪除
app.delete('/todos/:id', (req, res) => {
  const id = Number(req.params.id)
  const exists = todos.some((t) => t.id === id)
  if (!exists) {
    return res.status(404).json({ error: '找不到這筆 todo' })
  }
  todos = todos.filter((t) => t.id !== id)
  res.status(204).send()
})
```

> 🧠 為什麼用 **PATCH** 而不是 PUT？因為我們常常只想改「完成狀態」一個欄位，不想每次都把整筆重送。→ [概念卡：HTTP 狀態碼 § PUT vs PATCH](../concepts/http-狀態碼.md)

測試：

```bash
curl -X PATCH http://localhost:3000/todos/1 -H "Content-Type: application/json" -d '{"completed":true}'
curl -X DELETE http://localhost:3000/todos/1
```

> ✅ **檢查點 C**：五個路由（列表、單筆、新增、更新、刪除）都能正常運作，找不到的 id 會回 404。

## 步驟 5：記錄每個請求（自訂 middleware）

開發時想知道「進來了哪些請求、花多久」。在 `app.use(express.json())` 後面加：

```js
app.use((req, res, next) => {
  const start = Date.now()
  res.on('finish', () => {
    console.log(`${req.method} ${req.originalUrl} → ${res.statusCode} (${Date.now() - start}ms)`)
  })
  next()
})
```

現在每打一次 API，終端機就會印出一行記錄。

> 🧠 middleware 的執行順序、`next()` 的作用 → [概念卡：Express Middleware](../concepts/express-middleware.md)

## 步驟 6：收尾——404 與錯誤處理

把這兩段加在**所有路由的最後面**：

```js
// 沒有任何路由匹配時
app.use((req, res) => {
  res.status(404).json({ error: `找不到路徑 ${req.method} ${req.originalUrl}` })
})

// 錯誤處理 middleware（四個參數，一定放最後）
app.use((err, req, res, next) => {
  console.error(err)
  res.status(err.status || 500).json({ error: err.message || '伺服器發生錯誤' })
})
```
