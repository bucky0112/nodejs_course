## 步驟 1：同步 vs 非同步

Node 是**單執行緒**的。碰到「要等」的事情時怎麼處理，是這門課最核心的直覺。

**同步版** `sync.js`：會卡住，一個讀完才讀下一個。

```js
import fs from 'node:fs'

console.log('--- 同步開始 ---')
console.time('同步總耗時')
fs.readFileSync('file1.txt', 'utf8')
console.log('讀取檔案 1 完成')
fs.readFileSync('file2.txt', 'utf8')
console.log('讀取檔案 2 完成')
console.log('這句話必須等上面都讀完才會出現')
console.timeEnd('同步總耗時')
```

**非同步版** `async.js`：發出請求就先往下走。

```js
import fs from 'node:fs/promises'

async function asyncDemo() {
  console.log('--- 非同步開始 ---')
  console.time('非同步總耗時')

  const p1 = fs.readFile('file1.txt', 'utf8').then(() => console.log('非同步：檔案 1 完成'))
  const p2 = fs.readFile('file2.txt', 'utf8').then(() => console.log('非同步：檔案 2 完成'))

  console.log('當檔案還在讀取時，我已經執行到這行了！')
  await Promise.all([p1, p2])
  console.timeEnd('非同步總耗時')
}

asyncDemo()
```

各跑一次，注意印出的**順序**：

```bash
node sync.js
node async.js
```

非同步版裡，「我已經執行到這行了」會**早於**「檔案完成」出現，這就是非同步的精髓：Node 把讀檔交出去，自己先繼續跑。

> 🧠 為什麼單執行緒還要非同步、同步會害伺服器怎樣 → [概念卡：Node.js 的非同步機制](../concepts/非同步機制.md)

> ✅ **檢查點 A**：非同步版的「執行到這行」印在「檔案完成」之前。

## 步驟 2：非同步的三代寫法

「結果晚點才到」要怎麼接？歷史上有三種寫法，做的是同一件事。建立 `three-ways.js`，用三種寫法各做一次「先讀 file1，再讀 file2，然後一起印出來」：

```js
import fs from 'node:fs'
import fsPromises from 'node:fs/promises'

const file1 = new URL('./file1.txt', import.meta.url)
const file2 = new URL('./file2.txt', import.meta.url)

// 1. callback：結果從參數傳回來，下一步只能寫在裡面
function withCallback(done) {
  fs.readFile(file1, 'utf8', (err, a) => {
    if (err) return done(err)
    fs.readFile(file2, 'utf8', (err, b) => {
      if (err) return done(err)
      console.log('[callback]', a.trim(), b.trim())
      done(null)
    })
  })
}

// 2. Promise：用 .then() 一步一步串起來
function withPromise() {
  let a
  return fsPromises
    .readFile(file1, 'utf8')
    .then((content) => {
      a = content
      return fsPromises.readFile(file2, 'utf8')
    })
    .then((b) => console.log('[Promise]', a.trim(), b.trim()))
}

// 3. async/await：讀起來像同步，實際上不卡執行緒
async function withAsyncAwait() {
  const a = await fsPromises.readFile(file1, 'utf8')
  const b = await fsPromises.readFile(file2, 'utf8')
  console.log('[async/await]', a.trim(), b.trim())
}

withCallback(async (err) => {
  if (err) return console.error('callback 出錯：', err.message)
  try {
    await withPromise()
    await withAsyncAwait()
  } catch (err) {
    console.error('出錯：', err.message)
  }
})
```

```bash
node three-ways.js
```

> 💡 `new URL('./file1.txt', import.meta.url)` 是「相對於這支程式檔」的路徑，不管你在哪個資料夾執行都讀得到。

三種寫法印出來的內容一樣。差別在**錯誤怎麼接**：

| 寫法 | 錯誤從哪裡來 |
|---|---|
| callback | 第一個參數 `err` |
| Promise | `.catch()` |
| async/await | `try / catch` |

本課程之後全部用 async/await。

> ✅ **檢查點 B**：三行輸出內容相同，依序是 `[callback]`、`[Promise]`、`[async/await]`。

## 步驟 3：事件迴圈決定執行順序

非同步的工作完成後，回呼函式不是「馬上」執行，而是排進佇列，等**事件迴圈**輪到它。建立 `event-loop.js`，**先猜**它會印出什麼順序，再執行：

```js
console.log('1. 同步：第一行')

setTimeout(() => {
  console.log('5. timer：setTimeout 0 毫秒')
}, 0)

Promise.resolve().then(() => {
  console.log('3. microtask：Promise.then')
})

queueMicrotask(() => {
  console.log('4. microtask：queueMicrotask')
})

console.log('2. 同步：最後一行')
```

```bash
node event-loop.js
```

印出來會照 1 → 2 → 3 → 4 → 5 的順序。規則只有三條：

```
① 同步程式碼一路跑完                    → 1、2
② 清空 microtask 佇列                    → 3、4（Promise 的 .then、await 之後的程式）
③ 輪到 timer 等其他佇列                  → 5（就算設定 0 毫秒也一樣要排隊）
```

> ⚠️ `setTimeout(fn, 0)` 不是「立刻執行」，而是「最快在下一輪執行」。同步程式碼如果跑很久，timer 就得一直等，這也是為什麼不能在伺服器裡寫會卡很久的同步程式。

> ✅ **檢查點 C**：你猜的順序跟實際輸出一致，並說得出 3 為什麼比 5 先印。
