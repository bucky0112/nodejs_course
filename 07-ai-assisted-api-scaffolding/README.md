# 第 7 堂 · AI 輔助生成 API 架構：寫規則、請 AI 產生、自己審查

> 對應課綱第 7 堂（用 AI 產 scaffold 並審查）。延續第 6 堂的三層 todo app。這是本課第一次使用 AI 開發工具。

---

## 關於這門課怎麼用 AI

AI 是**放大器**：你的基礎越好，越能用好 AI；還看不懂程式碼時就用 AI，放大的是錯誤。所以：

- 第 1–6 堂不用 AI，先建立判斷程式碼對不對的能力。
- 第 7、8 堂開始用 AI，而且一定是「先寫規則、再請 AI 產生、自己審查與測試」。
- 第 9–12 堂是新主題（SQL、Prisma），先不用 AI，學會了再說。
- 第 13 堂把資料層的規則也加進規則檔，再和 AI 協作。

**AI 產生的程式碼，你能解釋才採納。**

---

## ① 這堂你會做出什麼、搞懂什麼

**做出**：一份寫著前 6 堂規則的 `AGENTS.md`，請 AI 依規則替 todo app 產生 `/notes` 資源，並完成一張審查表。

**搞懂**：
- 為什麼要先寫規則檔，規則要寫到多具體
- `AGENTS.md` 和 `CLAUDE.md` 的關係
- 怎麼把需求寫清楚（API 對照表）
- 怎麼逐條對照規則審查 AI 的產出，決定採納、修改或退回

## ⑤ 驗收 + 挑戰

> ✏️ **課堂練習**：做完工作坊後，先試[課堂練習](./課堂練習.md)：審查一份不守規則的程式碼，找出它違反了哪幾條。

### 驗收：確認你的成果能跑

```bash
cd 完成版
npm install
npm run dev
```

逐一確認：

- [ ] 專案根目錄有 `AGENTS.md` 和 `CLAUDE.md`
- [ ] `/notes` 的五個路由都有，狀態碼符合 API 對照表
- [ ] notes 的 controller 沒有 `if`、try/catch、`HttpError`
- [ ] notes 的 service 沒有 `req`、`res`
- [ ] `app.js`、`errorHandler.js`、`package.json` 沒有被 AI 改動
- [ ] 你的審查表每一列都有「採納、修改或退回」和理由

### 挑戰（可選，加深理解）

1. **加一條規則**：讓 `GET /notes` 把 `pinned: true` 的排在前面。先想好這該寫進需求還是規則檔，再請 AI 實作並審查。
2. **找規則的漏洞**：故意請 AI「用最快的方式加一個 `/tags`，不用管規則」，看它違反了哪些規則。想想有沒有哪條規則要寫得更明確。
3. **換一個工具**：用另一個 AI 工具重做步驟 3，比較兩者產出的差異。
