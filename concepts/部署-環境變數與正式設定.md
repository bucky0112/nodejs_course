# 概念卡：部署——環境變數與正式設定

> 一句話：上線不是把開發那套原封不動搬上去——要把祕密放進平台的環境變數、讓 app 聽平台給的 port、並把開發用的寬鬆設定切成正式模式。

---

## 一、祕密絕不進版控

`.env` 裡的 `DATABASE_URL`、`JWT_SECRET`、各種金鑰——這些**永遠不該 commit**（所以 `.gitignore` 要有 `.env`）。上線時改用**平台的環境變數**設定（Railway / Vercel 等都有介面填）。

> 為什麼：版控歷史是永久的，祕密一旦 commit 過，就算之後刪掉也算外洩。

---

## 二、Port 要聽平台的

開發時我們寫 `const PORT = process.env.PORT || 3000`。這個 `|| 3000` 是給本機用的；**正式環境平台會自己指定 port**，透過 `process.env.PORT` 給你。所以一定要讀環境變數，不能寫死 3000，否則平台連不到你的 app。

```js
const PORT = process.env.PORT || 3000   // ✓ 本機用 3000，上線聽平台的
app.listen(PORT, ...)
```

---

## 三、開發 vs 正式的設定切換

有些設定在開發與正式要不一樣，常用 `process.env.NODE_ENV` 來切：

```js
cookie: {
  secure: process.env.NODE_ENV === 'production',  // 正式走 HTTPS 才設 true
}
```

正式環境平台通常會自動把 `NODE_ENV` 設成 `production`。

---

## 四、資料庫遷移要在部署時跑

本機你手動 `npm run migrate`。上線時，每次部署若 schema 有變，也要把 migration 套到正式資料庫。做法是設定平台的「部署前指令（pre-deploy / release command）」：

```
npm run migrate
```

讓它在新版本啟動前自動跑，資料庫結構才會跟程式同步。

---

## 五、上線前檢查清單

- [ ] `.env` 在 `.gitignore` 裡，祕密改用平台環境變數
- [ ] `app.listen(process.env.PORT || ...)`
- [ ] `package.json` 有 `start` script（平台用它啟動）
- [ ] 正式資料庫的連線字串、JWT 密鑰等都設好
- [ ] migration 會在部署時執行
- [ ] 開發用的寬鬆設定（CORS 全開、secure:false…）切成正式值

---
