# 課堂練習：自己寫一個全域、一個路由層級的 middleware

> 這不是工作坊的延伸，而是**把這堂的核心重點再走一遍**，但這次沒有逐步指引，你得自己寫。
>
> 核心重點：middleware 的形狀 `(req, res, next)`；放行要呼叫 `next()`，攔下就直接回應；全域用 `app.use`，路由層級寫在路由參數裡；順序決定誰先跑。

在工作坊做完的 todo app 上，加兩個 middleware。

---

## 任務

**1. 全域 middleware `responseTime`**

- 對**每一個**請求，在回應的 header 加上 `X-Response-Time`，值是處理這個請求花了幾毫秒，例如 `X-Response-Time: 3ms`。
- 提示：header 要在回應送出**之前**設定。可以先記下開始時間，再包裝 `res.json`，或研究一下 `res.on('finish')` 為什麼在這裡行不通。

**2. 路由層級 middleware `requireJson`**

- 只掛在 `POST /todos` 上，而且要放在 `validateTitle` **前面**。
- 如果請求的 `Content-Type` 不是 `application/json`，直接回 **415**，body 是 `{ "error": "請用 JSON 格式送出資料" }`，不再往下走。
- 是 JSON 就呼叫 `next()` 放行。
- 提示：`req.is('application/json')`。

**明確規格**（這幾條就是這堂重點，別漏）：

- `responseTime` 用 `app.use` 掛，所有路由（包含 404）都要有 `X-Response-Time`。
- `requireJson` 不准用 `app.use` 掛，只能寫在 `app.post('/todos', ...)` 的參數裡。
- 攔下請求的那一支，**不准**呼叫 `next()`。
- 兩支都放在獨立的 `const`，不要直接寫成匿名函式塞進去。

> 💡 卡在「為什麼 header 設了卻沒出現」時，回去翻[概念卡：Express Middleware](../concepts/express-middleware.md)的執行順序。不要翻工作坊的程式碼照抄：憑記憶寫，寫不出來才回去看，這樣才練得到。

---

## 進階（行有餘力）

- 把兩支 middleware 搬到 `middleware/` 資料夾，各自一個檔案，再 `import` 回 `app.js`。
- 寫一個 `requestId` middleware：每個請求產生一個隨機 id（`crypto.randomUUID()`），放進 `req.id`，並在回應 header 加上 `X-Request-Id`。

---

## 自我檢核

```bash
# 1. 任何請求都有 X-Response-Time
curl -i http://localhost:3000/todos
curl -i http://localhost:3000/not-exist

# 2. 不是 JSON → 415
curl -i -X POST http://localhost:3000/todos -d 'title=買牛奶'

# 3. 是 JSON 但缺 title → 400（requireJson 放行、validateTitle 攔下）
curl -i -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{}'

# 4. 正常新增 → 201
curl -i -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"買牛奶"}'
```

- [ ] 1. 每個回應（包含 404）都有 `X-Response-Time` header
- [ ] 2. 非 JSON 的新增請求回 `415`
- [ ] 3. JSON 但缺 title 回 `400`，代表兩支 middleware 的順序正確
- [ ] 4. 正常新增回 `201`
- [ ] 5. `requireJson` 沒有用 `app.use` 掛
