# 課堂練習：替 todo 加一個新欄位

> 這不是工作坊的延伸，而是**把這堂的核心重點再走一遍**，但這次沒有逐步指引，你得自己寫。
>
> 核心重點：改資料表結構的流程是「改 `schema.prisma` → `migrate dev` 產生並套用 migration → `generate` → 改 service」；驗證規則寫在 service。

這個練習**不用 AI**。

---

## 任務

替 todo 加一個**截止日期** `dueDate`：

**1. 資料表**

- 欄位名稱：程式裡叫 `dueDate`，資料庫裡叫 `due_date`。
- 型別：日期時間，含時區（跟 `createdAt` 一樣）。
- **可以是空的**：不是每筆 todo 都有截止日。
- migration 名稱用 `add_due_date`。

**2. API**

| 方法 | 路徑 | 行為 |
|---|---|---|
| POST | `/todos` | 可以多帶 `dueDate`（ISO 格式字串，例如 `"2026-12-31T23:59:00+08:00"`），不帶就是 `null` |
| PATCH | `/todos/:id` | 可以更新 `dueDate`；送 `null` 代表清掉截止日 |
| GET | `/todos?overdue=true` | 只回傳**已過期**（有截止日、截止日比現在早、而且還沒完成）的 todo |

**明確規格**（這幾條就是這堂重點，別漏）：

- `dueDate` 不是合法的日期字串時回 **400**（提示：`new Date('亂打')` 會得到 `Invalid Date`，`isNaN(date.getTime())` 是 `true`）。
- 所有檢查都寫在 service；controller 只多傳一個 query 參數，不寫任何判斷。
- 不准手動改資料庫（不准用 `psql` 下 `ALTER TABLE`），一定要透過 migration。
- 產生的 migration 檔要留著，確認裡面的 SQL 是你預期的。

> 💡 卡在「Prisma 怎麼寫『小於現在時間』的條件」時，查 Prisma 文件的 filtering（`lt`、`not`）。不要翻工作坊照抄：先自己寫，寫不出來才回去看，這樣才練得到。

---

## 進階（行有餘力）

- 讓 `GET /todos` 的結果依截止日排序，沒有截止日的排在最後（提示：Prisma 的 `orderBy` 可以設定 `nulls`）。
- 打開 `add_due_date` 的 `migration.sql`，跟你在第 9 堂會寫的 `ALTER TABLE` 比較。

## 自我檢核

```bash
# 1. 有截止日 → 201，回應裡有 dueDate
curl -i -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"報稅","dueDate":"2020-05-31T23:59:00+08:00"}'

# 2. 沒有截止日 → 201，dueDate 是 null
curl -i -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"隨時都可以"}'

# 3. 日期亂打 → 400
curl -i -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"壞日期","dueDate":"明天"}'

# 4. 只看過期的 → 只有「報稅」
curl -i "http://localhost:3000/todos?overdue=true"

# 5. 清掉截止日 → 200，dueDate 變 null
curl -i -X PATCH http://localhost:3000/todos/<報稅的 id> -H "Content-Type: application/json" -d '{"dueDate":null}'
```

- [ ] 1. `prisma/migrations/` 多了一個 `_add_due_date` 資料夾，裡面的 SQL 新增了 `due_date` 欄位
- [ ] 2. `psql -d todo_app -c '\d todos'` 看得到 `due_date`，而且可以是 NULL
- [ ] 3. 上面五個請求的結果都符合預期
- [ ] 4. controller 沒有任何 `if` 判斷
- [ ] 5. 原本的 CRUD 照常運作
