# 第 6 堂工作坊：集中處理錯誤，並把 app 拆成三層

第 5 堂結尾我們發現：送一段壞掉的 JSON，API 會回一大段 HTML。另外，`找不到這筆 todo` 這個 404 在程式碼裡寫了三次。這一堂先用**錯誤處理 middleware** 把錯誤集中到一個出口，再用 `HttpError` 讓任何地方都能「拋出」錯誤，最後順勢把 `app.js` 拆成 routes、controllers、services 三層。

> 從[第 5 堂完成版](../05-restful-api-design/完成版/)接著做。想知道「為什麼這樣寫」，每一步都有連結指向對應的[概念卡](../concepts/)。
>
> 卡住了？每個檢查點都對得上 [`完成版/`](./完成版/) 裡的程式碼，可以直接比對。

---

## 步驟 0：看看現在的錯誤長什麼樣

伺服器跑起來，打這兩個請求：

```bash
# 壞掉的 JSON
curl -i -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{bad'
```

再暫時加一個會出錯的路由，模擬程式自己寫壞了：

```js
app.get('/boom', (req, res) => {
  throw new Error('資料庫密碼是 abc123')
})
```

```bash
curl -i http://localhost:3000/boom
```

兩個都回 **HTML**，而且第二個把錯誤訊息（還有程式碼路徑）整個印給前端看。如果錯誤訊息裡剛好有機密，就直接洩漏了。

> ✅ **檢查點 A**：說得出現在的錯誤回應有哪兩個問題（格式不是 JSON、會洩漏內部訊息）。

---

## 步驟 1：錯誤處理 middleware，所有錯誤的出口

在**所有路由和 404 處理的後面**，加一個**四個參數**的 middleware：

```js
app.use((err, req, res, next) => {
  // express.json() 解析失敗：前端送了壞掉的 JSON
  if (err.type === 'entity.parse.failed') {
    return res.status(400).json({ error: '請求的 JSON 格式錯誤' })
  }

  const status = err.status || 500

  // 5xx 是伺服器自己的問題：完整錯誤印在 log，回應只給通用訊息
  if (status >= 500) {
    console.error(err)
    return res.status(status).json({ error: '伺服器發生錯誤' })
  }

  res.status(status).json({ error: err.message })
})
```

再打一次步驟 0 的兩個請求：壞掉的 JSON 回 `400 {"error":"請求的 JSON 格式錯誤"}`；`/boom` 回 `500 {"error":"伺服器發生錯誤"}`，密碼只出現在伺服器的終端機裡。

兩條規則：
- **四個參數一個都不能少**（就算 `next` 沒用到）。Express 靠參數數量認出它是錯誤處理器。
- **放在最後**。路由裡出的錯，會跳過後面一般的 middleware，直接找到它。

> 🧠 為什麼是四個參數、Express 5 怎麼接住 async 錯誤 → [概念卡：Express 的錯誤處理](../concepts/express-錯誤處理.md)

測完把 `/boom` 路由刪掉。

> ✅ **檢查點 B**：壞掉的 JSON 回 400 JSON；程式出錯回 500 JSON，回應裡看不到內部訊息。

## 步驟 2：HttpError，讓錯誤可以「拋出去」

現在每個路由都自己 `return res.status(404).json(...)`。改成**拋出**一個帶狀態碼的錯誤，交給步驟 1 的出口統一回應。

建立 `src/lib/httpError.js`：

```js
// 帶 HTTP 狀態碼的錯誤：拋出後，由錯誤處理 middleware 統一翻成回應。
export class HttpError extends Error {
  constructor(status, message) {
    super(message)
    this.status = status
  }
}
```

用法：

```js
throw new HttpError(404, '找不到這筆 todo')
```

錯誤處理 middleware 讀到 `err.status` 是 404，就回 `404 {"error":"找不到這筆 todo"}`。所有錯誤回應的格式都一樣是 `{ error: 訊息 }`，前端只要處理一種形狀。

> 💡 為什麼是 `throw` 而不是 `return res...`？因為之後檢查的程式會寫在**不認識 `res` 的地方**（下一步的 service）。拋出錯誤，不管在多深的函式裡，都能一路傳到出口。

> ✅ **檢查點 C**：說得出 `throw new HttpError(404, ...)` 最後是誰把它變成 HTTP 回應的。

## 步驟 3：拆成三層

`app.js` 現在什麼都管：路由、讀 `req`、驗證、存取資料、回應。沿著責任把它切成三層：

| 層 | 只做這些 | 不碰 |
|---|---|---|
| **route** | 宣告「哪個方法 + 路徑」對到哪個 controller | 任何邏輯 |
| **controller** | 讀 `req`、呼叫 service、設狀態碼、回 `res` | 驗證規則、資料存取 |
| **service** | 驗證 + 業務邏輯 + 資料存取；回純資料或拋 `HttpError` | `req` / `res` |

> 🧠 為什麼這樣切、每一層的邊界 → [概念卡：分層架構](../concepts/分層架構.md)

目標結構：

```
src/
├── app.js                       組裝：掛 middleware 與路由（不 listen）
├── server.js                    啟動：app.listen
├── lib/httpError.js
├── middleware/errorHandler.js   notFound + errorHandler
├── routes/
│   ├── index.js
│   └── todos.routes.js
├── controllers/todos.controller.js
└── services/todos.service.js
```

### 3-1 service：驗證 + 資料

建立 `src/services/todos.service.js`，記憶體資料搬到這裡，所有檢查都改成拋 `HttpError`：

```js
import { HttpError } from '../lib/httpError.js'

const todos = [
  { id: 1, title: '學會 Express', completed: false, createdAt: new Date().toISOString() },
  { id: 2, title: '搞懂路由', completed: true, createdAt: new Date().toISOString() },
]
let nextId = 3

function findOrThrow(id) {
  const todo = todos.find((t) => t.id === id)
  if (!todo) throw new HttpError(404, '找不到這筆 todo')
  return todo
}

function assertTitle(title) {
  if (typeof title !== 'string' || title.trim() === '') {
    throw new HttpError(400, 'title 必填，且必須是非空字串')
  }
}

export async function listTodos({ completed } = {}) {
  if (completed === undefined) return todos
  return todos.filter((t) => String(t.completed) === completed)
}

export async function getTodo(id) {
  return findOrThrow(id)
}

export async function createTodo({ title } = {}) {
  assertTitle(title)
  const todo = { id: nextId++, title: title.trim(), completed: false, createdAt: new Date().toISOString() }
  todos.push(todo)
  return todo
}

export async function updateTodo(id, { title, completed } = {}) {
  const todo = findOrThrow(id) // 先確認存在（404），再檢查欄位（400）
  if (title !== undefined) assertTitle(title)
  if (completed !== undefined && typeof completed !== 'boolean') {
    throw new HttpError(400, 'completed 必須是布林值')
  }
  if (title === undefined && completed === undefined) {
    throw new HttpError(400, '沒有提供要更新的欄位')
  }
  if (title !== undefined) todo.title = title.trim()
  if (completed !== undefined) todo.completed = completed
  return todo
}

export async function deleteTodo(id) {
  findOrThrow(id)
  todos.splice(todos.findIndex((t) => t.id === id), 1)
}
```

「找不到這筆 todo」現在只寫一次（`findOrThrow`）。第 4 堂的 `validateTitle` middleware 也不需要了，驗證規則集中在 service 的 `assertTitle`。

> 💡 資料在記憶體裡，為什麼函式還要寫 `async`？因為第 11 堂會把這裡換成資料庫查詢，那時一定是非同步的。現在就寫成 `async`，到時候只要改 service，controller 一行都不用動。

### 3-2 controller：只碰 HTTP

建立 `src/controllers/todos.controller.js`：

```js
import * as todosService from '../services/todos.service.js'

export async function list(req, res) {
  res.json(await todosService.listTodos({ completed: req.query.completed }))
}

export async function get(req, res) {
  res.json(await todosService.getTodo(Number(req.params.id)))
}

export async function create(req, res) {
  res.status(201).json(await todosService.createTodo(req.body))
}

export async function update(req, res) {
  res.json(await todosService.updateTodo(Number(req.params.id), req.body))
}

export async function remove(req, res) {
  await todosService.deleteTodo(Number(req.params.id))
  res.status(204).send()
}
```

注意：**這裡沒有任何 try/catch**。service 拋出的 `HttpError`，Express 5 會自動接住、轉給錯誤處理 middleware。

### 3-3 route：只指路

建立 `src/routes/todos.routes.js`：

```js
import { Router } from 'express'
import * as todosController from '../controllers/todos.controller.js'

export const todosRouter = Router()

todosRouter.get('/', todosController.list)
todosRouter.get('/:id', todosController.get)
todosRouter.post('/', todosController.create)
todosRouter.patch('/:id', todosController.update)
todosRouter.delete('/:id', todosController.remove)
```

和 `src/routes/index.js`，把所有資源的 router 集中掛好：

```js
import { Router } from 'express'
import { todosRouter } from './todos.routes.js'

export const routes = Router()
routes.use('/todos', todosRouter)
```

### 3-4 錯誤處理搬進 middleware 資料夾

建立 `src/middleware/errorHandler.js`，把第 4 堂的 404 處理和步驟 1 的錯誤處理器搬進來，各自 export：

```js
export function notFound(req, res) {
  res.status(404).json({ error: `找不到路徑 ${req.method} ${req.originalUrl}` })
}

export function errorHandler(err, req, res, next) {
  // ……步驟 1 的內容
}
```

### 3-5 app.js 與 server.js

`src/app.js` 只負責組裝，**不呼叫 listen**：

```js
import express from 'express'
import morgan from 'morgan'
import { routes } from './routes/index.js'
import { notFound, errorHandler } from './middleware/errorHandler.js'

export const app = express()

app.use(express.json())
app.use(morgan('dev'))

app.use(routes)

app.use(notFound)
app.use(errorHandler) // 一定放最後
```

`src/server.js` 負責啟動：

```js
import { app } from './app.js'

const PORT = process.env.PORT || 3000
app.listen(PORT, () => {
  console.log(`伺服器啟動：http://localhost:${PORT}`)
})
```

為什麼要分兩個檔？[第 8 堂](../08-testing-and-validation/)寫測試時，測試程式會直接 `import { app }` 來發請求，不需要真的開一個 port。

最後刪掉舊的 `app.js`，把 `package.json` 的指令改成新的進入點：

```json
"main": "src/server.js",
"scripts": {
  "dev": "node --watch src/server.js",
  "start": "node src/server.js"
}
```

> ✅ **檢查點 D（完成版）**：`npm run dev` 跑得起來，第 5 堂驗收清單的每一條結果都跟以前一樣；壞掉的 JSON 回 400 JSON。你的 `src/` 應該跟 [`完成版/src/`](./完成版/src/) 一致。

- 新資源 = 新增一組 route、controller、service
