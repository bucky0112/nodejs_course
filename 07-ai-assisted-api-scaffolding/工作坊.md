# 第 7 堂工作坊：把規則寫給 AI，請它產生新資源，再由你審查

前 6 堂你親手寫出了 todo API，也建立了一套規則：三層結構、狀態碼、錯誤怎麼拋。這一堂第一次請 AI 幫忙寫程式。流程是：

```
把前 6 堂的規則寫成規則檔 → 寫清楚需求請 AI 產生 /notes → 逐條對照規則審查 → 測試 → 決定採納或退回
```

**AI 產生的程式碼，你能解釋才採納。**你看得懂、知道它對不對，AI 才是幫你加速；看不懂就照單全收，AI 放大的是錯誤。

> 從[第 6 堂完成版](../06-error-handling/完成版/)接著做。
>
> 卡住了？每個檢查點都對得上 [`完成版/`](./完成版/)，可以直接比對。

---

## 步驟 0：準備 AI 開發工具

任何一種能讀寫專案檔案的 AI 開發工具都可以，例如 Claude Code、Codex、GitHub Copilot 的 agent 模式。在 todo app 的專案根目錄打開它，確認它看得到 `src/` 資料夾。

> 💡 不同工具讀的規則檔名稱不一樣：Codex、Copilot 等工具讀 `AGENTS.md`，Claude Code 讀 `CLAUDE.md`。我們把規則寫在 `AGENTS.md`，再讓 `CLAUDE.md` 指向它，一份規則兩邊都能用。

---

## 步驟 1：先看看沒有規則會怎樣

先**不寫任何規則檔**，直接對 AI 說：

```
幫我加一個 /notes 的 CRUD API
```

看它產生了什麼，先**不要採納**（如果工具直接改了檔案，用 `git stash` 或 `git checkout .` 還原）。觀察幾件事：

- 它把程式碼放在哪裡？有照 routes / controllers / services 分嗎？
- 新增成功回 200 還是 201？
- 錯誤是 `res.status(...)` 直接回，還是拋 `HttpError`？
- 有沒有加 try/catch？有沒有裝新套件？

每次結果可能都不一樣。重點是：**AI 不知道你的專案有什麼規則**，它會用它自己最常看到的寫法。

> ✅ **檢查點 A**：說得出至少兩個 AI 的產出跟前 6 堂規則不一樣的地方。

---

## 步驟 2：把前 6 堂的規則寫成規則檔

在專案根目錄建立 `AGENTS.md`。內容就是你這 6 堂學到的規則，每一條都附上理由，讓 AI 知道為什麼要這樣做。

完整內容在 [`完成版/AGENTS.md`](./完成版/AGENTS.md)，先讀一遍，確認每一條你都知道是哪一堂學的：

| 規則 | 來自 |
|---|---|
| ESM、Express 5、不加新套件 | 第 1、3 堂 |
| 三層結構、各層不准做什麼 | 第 6 堂 |
| 新 router 掛在 `routes/index.js`，不動 `app.js` | 第 6 堂 |
| RESTful 網址、狀態碼表、PATCH、先 404 再 400、`nextId++` | 第 3、5 堂 |
| 拋 `HttpError`、controller 不寫 try/catch、錯誤形狀 `{ error }` | 第 6 堂 |
| 完成後列出檔案與 curl 測試指令 | 方便你審查 |

再建立 `CLAUDE.md`，內容只有一行：

```
@AGENTS.md
```

> 💡 規則要寫得**具體到能檢查**。「程式碼要乾淨」AI 沒辦法照做、你也沒辦法檢查；「controller 不准出現 try/catch」就很明確。

> ✅ **檢查點 B**：專案根目錄有 `AGENTS.md` 和 `CLAUDE.md`，你能指出每一條規則是哪一堂學的。

---

## 步驟 3：寫清楚需求，請 AI 產生 /notes

規則檔說的是「怎麼寫」，需求要說的是「寫什麼」。用第 5 堂學的 API 對照表把需求講清楚：

```
請依照 AGENTS.md 的規則，新增一個 notes 資源（隨手筆記），存在記憶體。

資料形狀：
{ id: 1, text: '記得買牛奶', pinned: false, createdAt: '2026-...' }

API：
| 方法   | 路徑        | 行為                         | 狀態碼          |
| GET    | /notes      | 回傳全部                     | 200             |
| GET    | /notes/:id  | 回傳單筆                     | 200 / 404       |
| POST   | /notes      | 新增，text 必填，pinned 選填 | 201 / 400       |
| PATCH  | /notes/:id  | 更新 text 或 pinned          | 200 / 400 / 404 |
| DELETE | /notes/:id  | 刪除                         | 204 / 404       |

驗證：
- text 必須是非空字串
- pinned 必須是布林值，新增時沒給就是 false
- PATCH 什麼欄位都沒給時回 400
```

送出，等 AI 產生程式碼。**先不要採納**，進到下一步審查。

> ✅ **檢查點 C**：AI 產生了程式碼，並列出它改了哪些檔案。

---

## 步驟 4：逐條對照規則審查

拿 `AGENTS.md` 當檢查表，一條一條看 AI 的產出。用 `git diff` 看它改了什麼：

```bash
git status
git diff
```

建議照這個順序看：

1. **改了哪些檔案？** 應該只有新增 `notes.routes.js`、`notes.controller.js`、`notes.service.js`，以及修改 `routes/index.js`。動到 `app.js`、`errorHandler.js` 或 `package.json` 都要問為什麼。
2. **route 檔**：只有 `Router()` 和路由宣告嗎？
3. **controller 檔**：有沒有 `if`、try/catch、`HttpError`？狀態碼是 201、204 嗎？id 有轉成數字嗎？
4. **service 檔**：有沒有 `req`、`res`？驗證寫齊了嗎？「找不到」的訊息是不是只寫一次？更新時是不是先檢查 404？id 是用計數器嗎？
5. **你看不懂的地方**：有任何一行你說不出它在做什麼，就問 AI「這一行在做什麼、為什麼要這樣寫」，搞懂之前不採納。

把審查結果寫成一張表：

| 檔案 | 違反哪一條規則／有什麼問題 | 採納、修改還是退回 | 理由 |
|---|---|---|---|
| | | | |

> ⚠️ 規則寫了 AI 也不一定每條都照做。這就是為什麼審查不能省：**規則檔降低出錯的機率，審查才是把關**。

> ✅ **檢查點 D**：完成審查表，每個你採納的地方都說得出它在做什麼。

---

## 步驟 5：測試，再請 AI 修正

用 AI 附上的 curl 指令（或自己寫）實際打每個路由，特別是錯誤情境：

```bash
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{"text":"開會"}'          # 201
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{}'                     # 400
curl -i -X PATCH http://localhost:3000/notes/999 -H "Content-Type: application/json" -d '{"pinned":"x"}'    # 404，不是 400
curl -i -X PATCH http://localhost:3000/notes/1 -H "Content-Type: application/json" -d '{}'                  # 400
curl -i -X DELETE http://localhost:3000/notes/1                                                              # 204
curl -i -X POST http://localhost:3000/notes -H "Content-Type: application/json" -d '{bad'                    # 400
```

審查或測試發現問題時，請 AI 修正。**指出是哪一條規則**，比只說「有錯」有效得多：

```
notes.controller.js 的 update 裡有 try/catch，違反 AGENTS.md 第 14 條，請移除。
```

修到審查表全部處理完、測試全部通過，才 commit。

> ✅ **檢查點 E（完成版）**：上面每個請求的狀態碼都對，`/todos` 照常運作。你的 notes 三個檔案行為應該跟 [`完成版/src/`](./完成版/src/) 一致（寫法可以不同）。

---

## 完成！

你第一次跟 AI 協作：先把規則寫下來，再交代需求，最後自己審查、測試。AI 寫得快，但**判斷對不對的是你**，你能這樣判斷，靠的是前 6 堂親手寫過一遍。
