# 工作坊：把單檔 todo app 重構成三層

M3 的成品能跑，但它的 `app.js` 已經長到一兩百行：所有路由、驗證、DB 查詢、錯誤回應全擠在同一個檔。功能沒問題，但**難讀、難測、難改**——加一個 endpoint 要捲老半天，想單獨測一段業務邏輯得整台伺服器起起來。

這一章不加任何功能，只做一件事：**沿著責任把它切開**。終點是 `routes → controllers → services` 三層，API 行為和 M3 一字不差。

> 起點 = [M3 完成版](../05-relations/完成版/)（單檔 `app.js` + `src/db/`）。卡住了？對照本章 [`完成版/`](./完成版/)。
>
> 🧠 為什麼要拆、拆成幾層才剛好 → [概念卡：分層架構](../concepts/分層架構.md)

## 先感受一下痛

打開 M3 的 `app.js`，看這一段 `POST /todos`：

```js
app.post('/todos', async (req, res) => {
  const { title, listId } = req.body
  if (typeof title !== 'string' || title.trim() === '') {   // ← 驗證
    return res.status(400).json({ error: 'title 必填' })     // ← HTTP 細節
  }
  if (listId != null) {
    const list = await db.query.lists.findFirst({ where: eq(lists.id, Number(listId)) })  // ← DB
    if (!list) return res.status(400).json({ error: '指定的 listId 不存在' })
  }
  const [todo] = await db.insert(todos).values({ ... }).returning()  // ← DB
  res.status(201).json(todo)                                          // ← HTTP 細節
})
```

一個 handler 同時在做：**讀 HTTP、驗證、打 DB、設狀態碼**。四件事黏在一起。我們的目標是把它們分到三層，每層只管一件事。

> 三層各自只准碰什麼 → [概念卡：分層架構 §二](../concepts/分層架構.md)

## 里程碑 1：`app.js` / `server.js` 分離 + 抽出錯誤處理

先不動任何路由邏輯，只調整「外殼」。

**① 建立 `src/lib/httpError.js`**——一個帶 HTTP 狀態碼的錯誤類別，給之後的 service 拋：

```js
// src/lib/httpError.js
export class HttpError extends Error {
  constructor(status, message) {
    super(message)
    this.status = status
  }
}
```

**② 建立 `src/middleware/errorHandler.js`**——把 M3 結尾「找不到路徑回 404」和「全域錯誤回 500」抽出來：

```js
// src/middleware/errorHandler.js

// 沒有任何路由命中 → 404
export function notFound(req, res) {
  res.status(404).json({ error: `找不到路徑 ${req.method} ${req.originalUrl}` })
}

// 全域錯誤出口：HttpError 帶 status；其餘視為 500。必須是 4 個參數。
export function errorHandler(err, req, res, next) {
  console.error(err)
  res.status(err.status || 500).json({ error: err.message || '伺服器發生錯誤' })
}
```

**③ 把 `app.js` 拆成 `src/app.js`（組裝）+ `src/server.js`（啟動）**。

`src/app.js` 建立 app、掛 middleware、掛路由，最後 **export，但不 `listen`**（路由先原封不動搬進來，下個里程碑再拆）：

```js
// src/app.js
import 'dotenv/config'
import express from 'express'
import { notFound, errorHandler } from './middleware/errorHandler.js'

export const app = express()
app.use(express.json())
// …（請求紀錄 middleware、目前所有 app.get/post/... 路由先照搬進來）

app.use(notFound)
app.use(errorHandler)   // ← 永遠放最後
```

`src/server.js` 只負責啟動：

```js
// src/server.js
import { app } from './app.js'

const PORT = process.env.PORT || 3000
app.listen(PORT, () => console.log(`伺服器啟動：http://localhost:${PORT}`))
```

別忘了把 `package.json` 的 `dev`/`start` 指向 `src/server.js`，DB 的相對 import 路徑也要跟著 app.js 的新位置調整。

> 🧠 組裝（app）與啟動（server）為何要分開、對測試有什麼好處 → [概念卡：分層架構 §三](../concepts/分層架構.md)
>
> ✅ **檢查點 A**：`npm run dev` 還跑得起來，M3 的請求行為不變；錯誤與 404 由 `errorHandler.js` 統一處理。

## 里程碑 2：拿 `todos` 開刀，拆出第一條三層

只挑 **一個資源** 拆，先建立肌肉記憶、馬上驗證，確定模式對了再複製。

**① service（`src/services/todos.service.js`）**——把業務邏輯 + 驗證 + DB 搬進來。**不碰 `req`/`res`**；驗證失敗或查無資料就 `throw new HttpError(...)`，成功就 `return` 純資料：

```js
import { eq, and, asc } from 'drizzle-orm'
import { db } from '../db/index.js'
import { todos, lists, tags, todoTags } from '../db/schema.js'
import { HttpError } from '../lib/httpError.js'

function shapeTodo(todo) {
  const { todoTags: links, ...rest } = todo
  return { ...rest, tags: (links ?? []).map((l) => l.tag) }
}

export async function listTodos() {
  const rows = await db.query.todos.findMany({
    with: { list: true, todoTags: { with: { tag: true } } },
    orderBy: asc(todos.id),
  })
  return rows.map(shapeTodo)
}

export async function createTodo({ title, listId }) {
  if (typeof title !== 'string' || title.trim() === '') {
    throw new HttpError(400, 'title 必填，且必須是非空字串')   // ← 不回 res，用拋的
  }
  if (listId !== undefined && listId !== null) {
    const list = await db.query.lists.findFirst({ where: eq(lists.id, Number(listId)) })
    if (!list) throw new HttpError(400, '指定的 listId 不存在')
  }
  const [todo] = await db.insert(todos).values({ title: title.trim(), listId: listId ?? null }).returning()
  return todo   // ← 回純資料，不碰狀態碼
}

// getTodo / updateTodo / deleteTodo / addTagToTodo / removeTagFromTodo 同理（見完成版）
```

**② controller（`src/controllers/todos.controller.js`）**——只碰 HTTP：讀 `req`、定狀態碼、回 `res`。注意它是**裸 async 函式，沒有 try/catch**：

```js
import * as todosService from '../services/todos.service.js'

export async function list(req, res) {
  res.json(await todosService.listTodos())
}

export async function create(req, res) {
  res.status(201).json(await todosService.createTodo(req.body))
}

export async function get(req, res) {
  res.json(await todosService.getTodo(Number(req.params.id)))
}
// update / remove / addTag / removeTag 同理（見完成版）
```

> ⚠️ **「沒有 try/catch，service 拋的 `HttpError` 怎麼會變成 400/404？」**——這是本章最容易卡住的點。答案：**Express 5 會自動接住 async handler 回傳的 rejected promise，幫你呼叫 `next(err)`**，把錯誤一路送到里程碑 1 的 `errorHandler`，由它依 `err.status` 翻成 400/404/500。**Express 4 不會**（async 拋錯會讓請求卡死，你得自己包 try/catch）——這正是本課鎖定 Express 5 的好處之一。所以 controller 才能保持這麼乾淨。
> 細節 → [概念卡：Express 的錯誤處理 §三](../concepts/express-錯誤處理.md)

**③ route（`src/routes/todos.routes.js`）**——只宣告「路徑 + method → 哪個 controller 函式」，零邏輯：

```js
import { Router } from 'express'
import * as todosController from '../controllers/todos.controller.js'

export const todosRouter = Router()
todosRouter.get('/', todosController.list)
todosRouter.get('/:id', todosController.get)
todosRouter.post('/', todosController.create)
todosRouter.patch('/:id', todosController.update)
todosRouter.delete('/:id', todosController.remove)
todosRouter.post('/:id/tags', todosController.addTag)
todosRouter.delete('/:id/tags/:tagId', todosController.removeTag)
```

**④ 在 `app.js` 掛上這條 router**，並把原本 `app.js` 裡的 `/todos*` 路由刪掉（`lists`/`tags` 暫時留著沒搬，先讓 todos 這條跑通）：

```js
import { todosRouter } from './routes/todos.routes.js'
app.use('/todos', todosRouter)
```

**先驗證再往下**：

```bash
curl localhost:3000/todos
curl -X POST localhost:3000/todos -d '{"title":"寫週報"}' -H 'Content-Type: application/json'
curl -X POST localhost:3000/todos -d '{}' -H 'Content-Type: application/json'   # ← 應回 400
curl localhost:3000/todos/99999                                                  # ← 應回 404
```

> ✅ **檢查點 B**：`todos` 全套（含貼/撕標籤）行為與 M3 一致；打開 `controller` 看不到 SQL、打開 `service` 看不到 `req`/`res`。

## 里程碑 3：把同一套模式套到 `lists`、`tags`

模式已經驗證過了，剩下就是**機械式複製**。`lists`、`tags` 比 todos 單純（只有 list / create），更好練手。

每個資源都產出三個檔，例如 lists：

```js
// src/services/lists.service.js —— 業務 + DB
export async function listLists() { /* db.select … */ }
export async function createList({ name }) {
  if (typeof name !== 'string' || name.trim() === '') throw new HttpError(400, 'name 必填')
  /* db.insert … return list */
}

// src/controllers/lists.controller.js —— 只碰 HTTP
export async function list(req, res) { res.json(await listsService.listLists()) }
export async function create(req, res) { res.status(201).json(await listsService.createList(req.body)) }

// src/routes/lists.routes.js —— 只宣告路徑
export const listsRouter = Router()
listsRouter.get('/', listsController.list)
listsRouter.post('/', listsController.create)
```

`tags` 完全同理。`app.js` 暫時長這樣（三條 router 各自掛）：

```js
app.use('/todos', todosRouter)
app.use('/lists', listsRouter)
app.use('/tags', tagsRouter)
```

到這裡，原本的 `app.js` 應該已經**沒有任何路由邏輯**了——所有 `app.get/post/...` 都搬進對應的 routes 檔。

> ✅ **檢查點 C**：`lists`、`tags` 也都拆成三層；`app.js` 裡找不到任何 SQL 或驗證。

## 里程碑 4：用 `routes/index.js` 匯總，`app.js` 收斂

`app.js` 掛三條 router 還行，但資源一多就會越掛越長。加一個**路由匯總點**，把「掛載」這件事收到一個檔：

```js
// src/routes/index.js
import { Router } from 'express'
import { todosRouter } from './todos.routes.js'
import { listsRouter } from './lists.routes.js'
import { tagsRouter } from './tags.routes.js'

export const routes = Router()
routes.use('/todos', todosRouter)
routes.use('/lists', listsRouter)
routes.use('/tags', tagsRouter)
```

`app.js` 最終收斂成清清爽爽的「**組裝 + 掛載**」——它只回答一個問題：「這個 app 由哪些零件組成？」

```js
// src/app.js
import 'dotenv/config'
import express from 'express'
import { routes } from './routes/index.js'
import { notFound, errorHandler } from './middleware/errorHandler.js'

export const app = express()
app.use(express.json())
app.use((req, res, next) => { /* 請求紀錄 */ next() })
app.use(routes)            // ← 一行掛上所有資源
app.use(notFound)
app.use(errorHandler)
```

最終結構：

```
src/
├── app.js                  組裝（建 app、掛 middleware/routes，export）
├── server.js               啟動（import app，listen）
├── lib/httpError.js        帶狀態碼的錯誤類別
├── middleware/errorHandler.js   notFound + 全域錯誤出口
├── routes/                 只宣告路徑 → controller
│   ├── index.js            匯總掛載
│   ├── todos.routes.js
│   ├── lists.routes.js
│   └── tags.routes.js
├── controllers/            只碰 HTTP
│   ├── todos.controller.js
│   ├── lists.controller.js
│   └── tags.controller.js
├── services/               業務邏輯 + 驗證 + DB
│   ├── todos.service.js
│   ├── lists.service.js
│   └── tags.service.js
└── db/                     schema + 連線（沿用 M3）
```

最後跑一遍 [M3 的那組請求](../05-relations/README.md#驗收)，結果應該**一字不差**。

> ✅ **檢查點 D（完成版）**：行為與 [`完成版/`](./完成版/) 一致。`app.js` 只剩組裝與掛載，每一層職責清楚。
