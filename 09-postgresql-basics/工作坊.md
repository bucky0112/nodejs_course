# 工作坊：用 SQL 建出 todo app 的資料庫

這一堂我們不寫 JavaScript，而是用純 SQL 把 todo app 的資料庫從零建起來。等到 [第 11 堂](../11-prisma-basics/) 改用 Prisma 接資料庫，你會發現它背後跑的 SQL 就是你今天手寫的這些。

> 卡住了？對照 [`完成版/`](./完成版/) 裡的 `schema.sql` / `seed.sql` / `queries.sql`。

## 步驟 0：建立資料庫並連進去

```bash
createdb todo_sql      # 建一個叫 todo_sql 的資料庫
psql -d todo_sql       # 連進去（出現 todo_sql=# 提示字元就成功了）
```

> 用 GUI（TablePlus / DBeaver）的話，新建一個連線、建立 `todo_sql` 資料庫即可。
>
> Windows 打指令出現「找不到指令」→ [概念卡：Windows 指令對照 § 四](../concepts/windows-指令對照.md)

## 步驟 1：建立第一張表 todos

```sql
CREATE TABLE todos (
  id         INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title      VARCHAR(200) NOT NULL,
  completed  BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

逐欄看：

- `id ... GENERATED ALWAYS AS IDENTITY PRIMARY KEY`：自動遞增的主鍵。
  > 💡 你可能在別的教材看過 `SERIAL`。`GENERATED AS IDENTITY` 是 PostgreSQL 10 之後**推薦**的標準寫法，`SERIAL` 是舊寫法。本課程一律用前者。
- `VARCHAR(200)`：最多 200 字元的字串；`NOT NULL` 表示必填。
- `BOOLEAN ... DEFAULT FALSE`：沒給值時預設 false。
- `TIMESTAMPTZ ... DEFAULT now()`：帶時區的時間戳，預設為現在。

確認表建好了：`\d todos`（psql 指令，顯示表結構）。

> ✅ **檢查點 A**：`todos` 表建立成功。

---

## 步驟 2：新增資料（CREATE）

```sql
INSERT INTO todos (title) VALUES ('學會 SQL');
INSERT INTO todos (title, completed) VALUES ('讀完 Express 文件', true);
```

注意：
- 文字要用**單引號** `'...'`；數字、布林不用。
- 沒列到的欄位（id、created_at、completed）會用預設值。**不要手動給 id**——它由資料庫自動產生。

---

## 步驟 3：查詢（READ）

```sql
-- 全部
SELECT * FROM todos;

-- 只要某些欄位
SELECT id, title FROM todos;

-- 條件 + 排序 + 限制筆數
SELECT id, title, completed
FROM todos
WHERE completed = false
ORDER BY created_at DESC
LIMIT 5;
```

`SELECT` 是最常用的指令，三個常搭配的子句：`WHERE`（過濾）、`ORDER BY`（排序）、`LIMIT`（取前幾筆）。

> ✅ **檢查點 B**：能新增資料、能用 WHERE/ORDER BY 查詢。

## 步驟 4：更新、刪除與「安全習慣」（UPDATE / DELETE）

```sql
-- 更新：把某筆標記為完成
UPDATE todos SET completed = true WHERE id = 1;

-- 刪除
DELETE FROM todos WHERE id = 2;
```

⚠️ **最危險的錯誤是忘了 `WHERE`**：

```sql
DELETE FROM todos;          -- ✗ 這會清空整張表！
UPDATE todos SET completed = true;   -- ✗ 這會改掉每一筆！
```

安全習慣（重要，請養成）：寫 `DELETE`/`UPDATE` 前，**先用相同的 `WHERE` 跑一次 `SELECT`**，確認會影響哪幾列、幾列。

```sql
-- 1. 先看看會命中誰
SELECT id, title FROM todos WHERE completed = true;
-- 2. 確認列數、內容都對，再把 SELECT ... 換成 DELETE
DELETE FROM todos WHERE completed = true;
```

`psql` 執行 `UPDATE` / `DELETE` 後會印出 `UPDATE 1`、`DELETE 3` 這樣的訊息——那個數字就是「實際動到幾列」，跟你預期的不一樣就要警覺。

> 💡 萬一真的下錯指令怎麼辦？下一堂 [第 10 堂](../10-postgresql-advanced/) 會學「交易」：先 `BEGIN`、確認結果再決定 `COMMIT` 或 `ROLLBACK`，給破壞性操作多一層保險。
>
> ✅ **檢查點 C**：能更新、刪除，並理解 WHERE 的重要性、養成先 SELECT 再動手的習慣。

## 步驟 5：加入關聯——清單(1:N) 與 標籤(M:N)

我們的 todo app 要長大了：todo 要能歸到「清單」、能貼「標籤」。

```sql
-- 清單：一個清單有多個 todo（1:N）
CREATE TABLE lists (
  id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(100) NOT NULL
);

-- 在 todos 加一個外鍵指向 lists
ALTER TABLE todos
  ADD COLUMN list_id INT REFERENCES lists(id) ON DELETE SET NULL;

-- 標籤
CREATE TABLE tags (
  id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(50) NOT NULL UNIQUE
);

-- todo 與 tag 的中介表（M:N）
CREATE TABLE todo_tags (
  todo_id INT NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
  tag_id  INT NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (todo_id, tag_id)
);
```

> 🧠 1:N 為什麼外鍵放在「多」邊、M:N 為什麼需要中介表、`ON DELETE` 那些選項是什麼意思 → [概念卡：SQL 關聯與 JOIN](../concepts/sql-關聯與join.md)

灌一些測試資料（或直接用 [`完成版/seed.sql`](./完成版/seed.sql)）：

```sql
INSERT INTO lists (name) VALUES ('工作'), ('生活'), ('學習');
INSERT INTO tags (name) VALUES ('緊急'), ('簡單'), ('長期');
-- 把現有 todo 歸到清單、貼標籤（id 請依你實際的資料調整）
UPDATE todos SET list_id = 1 WHERE id = 1;
INSERT INTO todo_tags (todo_id, tag_id) VALUES (1, 1);
```

## 步驟 6：JOIN——把分散的資料拼回來

```sql
-- 1:N：每筆 todo 連同它的清單名稱
SELECT t.title, l.name AS list
FROM todos t
JOIN lists l ON l.id = t.list_id;

-- M:N：每筆 todo 連同它的標籤（穿過中介表 JOIN 兩次）
SELECT t.title, tg.name AS tag
FROM todos t
JOIN todo_tags tt ON tt.todo_id = t.id
JOIN tags tg      ON tg.id = tt.tag_id;

-- 聚合 + LEFT JOIN：每個清單幾筆 todo（含空清單）
SELECT l.name, COUNT(t.id) AS todo_count
FROM lists l
LEFT JOIN todos t ON t.list_id = l.id
GROUP BY l.name;
```

> 🧠 為什麼算「每個清單幾筆」要用 `LEFT JOIN` 而不是 `JOIN`？→ [概念卡：SQL 關聯與 JOIN § 什麼時候用 LEFT JOIN](../concepts/sql-關聯與join.md)
