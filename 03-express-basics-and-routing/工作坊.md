# 第 3 堂工作坊：用 Express 做出 todo app 的骨架

這一堂我們從零建立 todo app 的後端 API。**它會一路帶到課程結束**：之後加 middleware、錯誤處理、測試，再接上資料庫，都是在今天這個骨架上長出來的。

> 跟著做就會動。想知道「為什麼這樣寫」，每一步都有連結指向對應的[概念卡](../concepts/)。
>
> 卡住了？每個檢查點都對得上 [`完成版/`](./完成版/) 裡的程式碼，可以直接比對。

---

## 步驟 0：建立專案

```bash
mkdir todo-app && cd todo-app
npm init -y
npm install express
```

打開 `package.json`，加上 `"type": "module"` 和 `dev` 指令：

```json
{
  "name": "todo-app",
  "type": "module",
  "scripts": {
    "dev": "node --watch app.js"
  }
}
```

> 💡 `node --watch` 是 Node 內建的功能：改檔案存檔後自動重啟，不用額外裝 nodemon。

---

## 步驟 1：跑起第一個伺服器

建立 `app.js`：

```js
import express from 'express'

const app = express()
const PORT = process.env.PORT || 3000

app.get('/', (req, res) => {
  res.send('todo app 啟動成功！')
})

app.listen(PORT, () => {
  console.log(`伺服器啟動：http://localhost:${PORT}`)
})
```

```bash
npm run dev
```

打開瀏覽器到 `http://localhost:3000`，看到「todo app 啟動成功！」就對了。

對照[第 1 堂](../01-nodejs-core-and-modules/)的原生 http 伺服器：`app.get('/', ...)` 一行就取代了一個 `if (req.url === '/')`，而且只會回應 **GET** 方法。

> ✅ **檢查點 A**：伺服器跑得起來、首頁有回應。

---

## 步驟 2：準備資料，並讓伺服器看得懂 JSON

在 `const app = express()` 後面加上：

```js
app.use(express.json())

const todos = [
  { id: 1, title: '學會 Express', completed: false, createdAt: new Date().toISOString() },
  { id: 2, title: '搞懂路由', completed: true, createdAt: new Date().toISOString() },
]
let nextId = 3
```

`app.use(express.json())` 讓 Express 把請求送來的 JSON 解析成 `req.body`。它是一個 middleware，[第 4 堂](../04-middleware/)會細講，今天先照抄。

> 資料先存在記憶體裡（伺服器重啟就消失）。我們刻意先把路由這層學透，第 11 堂再換成真正的資料庫。

---

## 步驟 3：路由與 request 的三個資料來源

一個請求帶來的資料，在 Express 裡會放在三個地方：

| 來源 | 例子 | 在 Express 裡 |
|---|---|---|
| 路由參數 | `/todos/2` 的 `2` | `req.params.id` |
| query string | `/todos?completed=true` 的 `completed=true` | `req.query.completed` |
| 請求主體 | POST 送來的 `{"title":"買牛奶"}` | `req.body.title` |

一次寫出三個路由，各用到一種：

```js
// 取得全部 todo；支援 query string：GET /todos?completed=true
app.get('/todos', (req, res) => {
  const { completed } = req.query // query string 的值永遠是字串
  if (completed === undefined) {
    return res.json(todos)
  }
  res.json(todos.filter((t) => String(t.completed) === completed))
})

// 取得單筆 todo：:id 是路由參數
app.get('/todos/:id', (req, res) => {
  const id = Number(req.params.id) // 路由參數也是字串，要自己轉數字
  const todo = todos.find((t) => t.id === id)
  if (!todo) {
    return res.status(404).json({ error: '找不到這筆 todo' })
  }
  res.json(todo)
})

// 新增 todo：資料從 req.body 拿
app.post('/todos', (req, res) => {
  const { title } = req.body
  if (typeof title !== 'string' || title.trim() === '') {
    return res.status(400).json({ error: 'title 必填，且必須是非空字串' })
  }

  const todo = {
    id: nextId++,
    title: title.trim(),
    completed: false,
    createdAt: new Date().toISOString(),
  }
  todos.push(todo)
  res.status(201).json(todo)
})
```

幾個要注意的地方：

- `req.params` 和 `req.query` 拿到的**都是字串**，`'2' === 2` 是 `false`，比對前要自己轉型。
- 回應用 `res.json(...)`，Express 會自動設好 `Content-Type: application/json`。要改狀態碼就在前面接 `res.status(...)`。
- 每個回應路徑都要 `return` 或者是最後一行，否則會「回應兩次」而報錯。
- **id 用遞增的 `nextId`，不是 `todos.length + 1`**：刪掉中間幾筆後，`length + 1` 會撞到已存在的 id。

> 🧠 404、400、201 這些狀態碼各代表什麼，[第 5 堂](../05-restful-api-design/)會整理。先有個印象就好 → [概念卡：HTTP 狀態碼](../concepts/http-狀態碼.md)

測試（用 VS Code 的 REST Client、Postman，或 curl）：

```bash
curl http://localhost:3000/todos
curl "http://localhost:3000/todos?completed=true"
curl http://localhost:3000/todos/2
curl http://localhost:3000/todos/999
curl -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"買牛奶"}'
```

> 💡 網址有 `?` 時要用引號包起來，有些終端機（例如 zsh）會把 `?` 當成特殊符號。

> ✅ **檢查點 B（完成版）**：上面五個請求都有預期的回應，`/todos/999` 回 404，新增成功回 201。你的 `app.js` 應該跟 [`完成版/app.js`](./完成版/app.js) 一致。
