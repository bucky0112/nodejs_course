# 課堂練習：用 params / query / body 寫一個新資源

> 這不是工作坊的延伸，而是**把這堂的核心重點再走一遍**，但這次沒有逐步指引，你得自己寫。
>
> 核心重點：路由對應 HTTP 方法與路徑；資料從 `req.params`、`req.query`、`req.body` 三個地方拿；用 `res.status().json()` 回應。

工作坊帶你做完 `/todos` 的三個路由。現在你要在**同一支 `app.js`** 裡，自己長出一個記憶體資源 `/books`（書單）。

---

## 任務

在 `/todos` 的程式碼下面，加上 `books` 的記憶體陣列與三個路由。

**資料形狀**（每本書），先放三本進陣列：

```js
{ id: 1, title: '原子習慣', author: 'James Clear', read: true }
```

**要做出的三個路由**：

| 方法 | 路徑 | 行為 |
|---|---|---|
| GET | `/books` | 回傳全部；帶 `?author=James Clear` 時只回傳該作者的書 |
| GET | `/books/:id` | 回傳單本；找不到回 404 |
| POST | `/books` | 新增一本，`read` 預設 `false` |

**明確規格**（這幾條就是這堂重點，別漏）：

- `GET /books?author=...` 的篩選從 `req.query` 拿，沒帶就回傳全部。
- `GET /books/:id` 的 id 從 `req.params` 拿，記得轉成數字再比對。
- `POST /books` 的資料從 `req.body` 拿；`title` 或 `author` 缺少、或不是非空字串，回 **400** 加一段 JSON 錯誤訊息。
- 新增成功回 **201**，並回傳剛建立的那本書。
- `id` 用一個遞增的 `nextBookId`，**不要**用 `books.length + 1`。

> 💡 卡住時回去翻工作坊步驟 3 的「三個資料來源」表格。不要翻 `/todos` 的程式碼照抄：憑記憶寫，寫不出來才回去看，這樣才練得到。

## 自我檢核

```bash
# 1. 列出全部 → 200 + 三本書
curl -i http://localhost:3000/books

# 2. 依作者篩選 → 只剩該作者的書
curl -i "http://localhost:3000/books?author=James%20Clear"

# 3. 查單本 → 200；查不存在的 → 404
curl -i http://localhost:3000/books/1
curl -i http://localhost:3000/books/999

# 4. 新增 → 201；缺 author → 400
curl -i -X POST http://localhost:3000/books -H "Content-Type: application/json" -d '{"title":"被討厭的勇氣","author":"岸見一郎"}'
curl -i -X POST http://localhost:3000/books -H "Content-Type: application/json" -d '{"title":"沒有作者"}'
```

- [ ] 1. 列表回 `200` 且是陣列
- [ ] 2. `?author=` 篩選正確，沒帶就回傳全部
- [ ] 3. 查單本找得到回 `200`、找不到回 `404`
- [ ] 4. 新增成功是 `201`，新書的 `read` 是 `false`
- [ ] 5. 缺 `title` 或 `author` 回 `400` 且有 JSON 錯誤訊息
