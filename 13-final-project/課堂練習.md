# 綜合專案：和 AI 一起完成一個新功能

> 用第 13 堂工作坊的方式，自己完成一個功能：寫規格 → 請 AI 依規則實作 → 審查 → 測試 → 能解釋才採納。
>
> 這份練習看的不只是功能做出來沒有，更看重**你的審查與判斷**。

---

## 任務

從下面選**一個**功能，加進第 13 堂的 todo app。

### 選項 A：截止日與過期清單

- todo 可以有截止日 `dueDate`（日期時間，可以是空的）。
- `POST /todos`、`PATCH /todos/:id` 可以設定或清除（`null`）截止日；日期不合法回 400。
- `GET /todos?overdue=true` 只回傳已過期（有截止日、早於現在、還沒完成）的 todo。

### 選項 B：子任務

- 一筆 todo 可以有多個子任務（subtask），每個子任務有 `title` 和 `completed`。
- `GET /todos/:id/subtasks`、`POST /todos/:id/subtasks`、`PATCH /todos/:id/subtasks/:subtaskId`、`DELETE /todos/:id/subtasks/:subtaskId`。
- 刪除 todo 時，它的子任務一起刪除。
- `GET /todos/:id` 的回應要有 `subtaskCount` 和 `doneSubtaskCount`。

### 選項 C：清單的統計與搜尋

- `GET /todos?q=關鍵字`：title 包含關鍵字的 todo（不分大小寫）。
- `GET /lists/:id/stats`：回傳這個清單的 todo 總數、已完成數、各優先順序的數量。
- 清單名稱不能重複，重複回 409（需要 migration）。

---

## 要繳交的東西

1. **規格**：在 `README.md`（或另一份文件）寫出這個功能的 API 對照表，包含每一種狀態碼。**先寫規格，再請 AI 實作。**
2. **規則檔**：如果這個功能需要新的規則，加進 `AGENTS.md`，並說明為什麼。
3. **程式碼**：功能本身、migration（如果有改 schema）、測試。
4. **審查表**：

   | 檔案 | 違反哪一條規則／有什麼問題 | 採納、修改還是退回 | 理由 |
   |---|---|---|---|
   | | | | |

   至少要有一列是「退回」或「修改」。如果 AI 第一次就全對，請 AI 用不守規則的方式再做一次，審查那一版。

5. **commit 紀錄**：每個 commit 訊息都說明**為什麼**。

**明確規格**（這幾條就是這堂重點，別漏）：

- 規格要在 AI 實作**之前**寫好；不准讓 AI 幫你決定規格。
- 改資料表一定要透過 migration，舊的 migration 檔不准修改。
- `npm test` 全部通過，而且新功能的每一種狀態碼都有測試。
- 審查表上採納的每一段程式碼，你都要能當場解釋它在做什麼。
