# 工作坊：把 todo app 搬上 Supabase + 加 Realtime

這章是進階旁支。重點不是重學 CRUD，而是看「Supabase 就是託管的 PostgreSQL」，以及它獨有的 Realtime。

> 卡住了？對照 [`完成版/`](./完成版/)。需要 Supabase 帳號才能跑。

---

## 步驟 1：建專案、拿金鑰與連線字串

1. 在 [Supabase](https://supabase.com/) 建一個免費專案。
2. **Project Settings → API**：複製 `SUPABASE_URL` 與 **publishable key**（`sb_publishable_...`）。
3. **Connect**（頁面上方按鈕）：複製 **Session pooler** 的連線字串（主機是 `...pooler.supabase.com`）。

> ⚠️ publishable key 不是 JWT（不是 `eyJ...`）；連線字串要用 Dashboard 給的 pooler 格式，別自己手刻直連。
> 🧠 [概念卡：Supabase 的金鑰與連線](../concepts/supabase-金鑰與連線.md)
>
> ✅ **檢查點 A**：拿到金鑰與 pooler 連線字串。

---

## 步驟 2：把 todo app 指向 Supabase（不改任何程式）

拿你 [M2]（或更後面）的 todo app，只改 `.env` 的一行：

```
DATABASE_URL=postgresql://postgres.[REF]:[PWD]@aws-0-[REGION].pooler.supabase.com:6543/postgres
```

然後照常：

```bash
npm run migrate    # 把 schema 套到 Supabase 的 Postgres
npm run dev
```

你的 Drizzle 程式**一行都沒改**，todo 就存到 Supabase 了——因為 Supabase 底層就是 PostgreSQL。

> ✅ **檢查點 B**：todo app 跑在 Supabase 上，資料寫得進去（可在 Supabase 後台的 Table Editor 看到）。

---

## 步驟 3：加 Realtime——資料一變就收到

先在 Supabase 後台把 `todos` 表加入 Realtime：**Database → Publications**，把 `todos` 勾起來（或用 SQL `ALTER PUBLICATION supabase_realtime ADD TABLE todos;`）。

然後用 supabase-js 訂閱：

```js
import { createClient } from '@supabase/supabase-js'
const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_PUBLISHABLE_KEY)

supabase
  .channel('todos-changes')
  .on('postgres_changes', { event: '*', schema: 'public', table: 'todos' }, (payload) => {
    console.log(`[${payload.eventType}]`, payload.new ?? payload.old)
  })
  .subscribe()
```

跑 `npm run listen`，再去後台新增一筆 todo——終端機會**即時**印出來。

> 🧠 Realtime 其實是 Postgres logical replication 的包裝，不是「Postgres 做不到」 → [概念卡：Supabase Realtime](../concepts/supabase-realtime.md)
>
> ✅ **檢查點 C**：能即時收到 todos 的變化。

---

## 步驟 4：認識 RLS

Supabase 讓前端能直接用 publishable key 打資料庫——那「誰能存取什麼」靠 **RLS** 在資料庫層把關：

```sql
ALTER TABLE todos ENABLE ROW LEVEL SECURITY;

CREATE POLICY "只能看自己的 todo"
ON todos FOR SELECT
USING (auth.uid() = user_id);
```

> ⚠️ 公開表沒開 RLS + 用 publishable key = 任何人都能讀寫，這是 Supabase 最常見的漏洞。
> 🧠 [概念卡：Supabase RLS](../concepts/supabase-rls.md)
>
> ✅ **檢查點 D**：理解 RLS 是 Supabase 前端直連安全的根本。
