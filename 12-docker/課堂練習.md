# 課堂練習：修好一個壞掉的 Dockerfile

> 這不是工作坊的延伸，而是**把這章的核心重點再走一遍**——但這次沒有食譜，你得自己抓出問題。
>
> 核心重點：層快取怎麼利用、`.dockerignore` 為什麼重要、image 為什麼要小。

工作坊帶你一步步寫出一份「正確」的 `Dockerfile`。現在反過來：下面這份 `Dockerfile` **跑得起來，但寫得很糟**。你的任務是**親手把它修好**——靠的是理解，不是回去翻工作坊照抄。

---

## 題目：這份 Dockerfile 哪裡有問題？

把這份壞掉的版本放進你的 todo app 專案根目錄（蓋掉原本的 `Dockerfile`），先讓它 build 起來，再一個一個把毛病修掉：

```dockerfile
FROM node:22

WORKDIR /app

# 一次把整個資料夾都搬進去
COPY . .

RUN npm install

EXPOSE 3000
CMD ["node", "app.js"]
```

這份至少踩了 **4 個** 這章強調過的雷。請憑理解找出來並修正（提示在下面，但先別急著看，自己先想）：

- **基底映像太肥**：`node:22` 是完整版，塞了一堆 todo app 用不到的系統工具。換成這章用的瘦身版。
- **沒利用層快取**：`COPY . .` 在 `npm install` 之前，等於只要改任何一行程式碼，套件就得整個重裝一次。想想工作坊為什麼把 `COPY` 拆成兩段。
- **裝了多餘的東西**：production image 不需要 `devDependencies`（例如 `drizzle-kit`）。`npm install` 換成更適合 CI / production 的指令，並只裝正式相依。
- **沒有 `.dockerignore`**：`COPY . .` 會把本機的 `node_modules`、`.env`、`.git` 一起塞進 build context 甚至 image——拖慢 build、還可能把祕密打包進去。補一個 `.dockerignore`。

> 💡 卡在「為什麼要這樣排」時，回去翻 [概念卡：Docker image vs container § 四](../concepts/docker-image-vs-container.md)（layer / volume / 為什麼 image 要小）。**不要回去把工作坊的 `Dockerfile` 整段複製過來**——憑記憶改，改不動才回去看，這樣才練得到。

---

## 進階（行有餘力）

- 修好之後，量一下「只改一行程式碼、不動 `package.json`」時重新 build 有多快——對照修之前。你應該會看到 `npm` 那層直接命中快取（`CACHED`）。
- 想想：如果 `.env` 真的被 `COPY` 進 image，別人 `docker history` 或把 image 拆開就看得到你的祕密。這就是為什麼祕密要靠 `environment` / runtime 注入，而不是烤進 image。

## 自我檢核

把修好的版本 build 起來，逐條對照。**全過才算完成**：

```bash
# 0. 先記下「壞版」的 image 大小與 build 時間（修之前先量，等下對照）
docker build -t todo:before .
docker images todo:before        # 看 SIZE

# --- 改好 Dockerfile 與 .dockerignore 之後 ---

# 1. 修好的版本能 build 成功
docker build -t todo:after .

# 2. 比 image 大小：after 應該明顯比 before 小（換了 slim + 只裝 production 相依）
docker images | grep '^todo'

# 3. 驗層快取：不動 package.json，隨便改一行 app.js，再 build 一次
#    → npm 那層應顯示 CACHED，而不是重新 npm install
docker build -t todo:after .

# 4. 容器真的跑得起來、API 通（這題只需要 app 容器；用對外 5433 連 db，
#    或先 docker compose up -d db 把資料庫拉起來）
docker run --rm -p 3000:3000 --env-file .env todo:after &
curl -i localhost:3000/health    # 應回 {"status":"ok"} 之類的 200
```

- [ ] 1. 改好的 `Dockerfile` `docker build` 成功
- [ ] 2. `after` image 的 SIZE 明顯小於 `before`（基底換成 slim）
- [ ] 3. 只改程式碼、不動 `package.json` 時，再 build 會看到裝套件那層 `CACHED`
- [ ] 4. `.dockerignore` 存在，且至少擋掉 `node_modules` 和 `.env`
- [ ] 5. 容器跑起來後 `curl localhost:3000/health` 回 `200`

### 觀念題（用文字作答，不必寫程式）

1. **image vs container**：你 `docker build` 出來的是 image 還是 container？`docker run` 出來的又是哪個？用 class / instance 類比一句話講清楚。
2. **層快取**：為什麼「先 `COPY package*.json` 再 `npm ci`、最後才 `COPY . .`」會比「`COPY . .` 後 `npm install`」快很多？是哪一層被快取了？

> 五條 checkbox 全綠 + 答得出兩題觀念，代表你抓到了 Dockerfile 最常被寫壞、也最影響 build 速度與 image 大小的那幾點。
