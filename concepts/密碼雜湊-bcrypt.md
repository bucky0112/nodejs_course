# 概念卡：密碼雜湊與 bcrypt

> 一句話：密碼**絕不能存明文**，也不是「加密」起來——而是用 bcrypt 做**單向雜湊**，存成一段算得回去、卻解不回來的字串。

---

## 一、雜湊 ≠ 加密（重要）

| | 加密（encryption） | 雜湊（hashing） |
|---|---|---|
| 可逆嗎 | 可以，有金鑰就能解回原文 | **不行**，單向、解不回來 |
| 用途 | 要保護、之後還要讀回的資料 | 驗證「是不是同一個東西」 |

密碼要的是後者：我們**不需要**把密碼解回來，只要能判斷「使用者這次輸入的，跟註冊時是不是同一個」。所以用雜湊，不用加密。

> ⚠️ 常見誤解：把 bcrypt 說成「加密演算法」。bcrypt 是基於 Blowfish 的**密碼雜湊**演算法，是單向的。

---

## 二、為什麼用 bcrypt，而不是 SHA-256

一般雜湊（MD5、SHA-256）是設計來「快」的——但密碼雜湊要的恰恰相反：**故意慢**，讓攻擊者沒辦法每秒試幾億個密碼暴力破解。

bcrypt 有兩個關鍵設計：

1. **自動加鹽（salt）**：每次雜湊都摻入一段隨機值，所以「兩個人用一樣的密碼，存進去的雜湊也不同」，攻擊者沒辦法用預先算好的彩虹表一次破一堆。
2. **可調成本（work factor）**：`cost = 10` 代表雜湊要做 2¹⁰ 輪。硬體變快，就把 cost +1（成本約翻倍），維持「對攻擊者夠慢」。

---

## 三、實際用法

```js
import bcrypt from 'bcrypt'

// 註冊：把明文密碼雜湊後才存
const passwordHash = await bcrypt.hash(password, 10) // 10 = cost factor
// 存進資料庫的 password_hash 欄位，長這樣：$2b$10$N9qo8uLOick...

// 登入：比對輸入的密碼與存的雜湊（bcrypt 會自己從雜湊裡取出 salt）
const ok = await bcrypt.compare(inputPassword, user.passwordHash)
```

注意：**salt 不必另外存**——它已經包在 `$2b$10$...` 這段雜湊字串裡了，`compare` 會自動取用。

---

## 四、兩個容易踩的雷

1. **bcrypt 有 72 bytes 輸入上限**：超過的部分會被默默截斷。極長密碼或想先 pre-hash 的情況要注意。
2. **登入失敗訊息要一致**：不論「帳號不存在」還是「密碼錯」，都回同一句「帳號或密碼錯誤」，否則會洩漏「哪些帳號存在」。

---

## 延伸
- 資料庫存的永遠是雜湊；就算資料庫外洩，攻擊者也拿不到明文密碼（但弱密碼仍可能被慢慢爆破，所以仍要求夠強的密碼）。
- 替代套件 `argon2` 是更新的選擇，概念一樣（慢、加鹽、可調成本）。
