# 第 11 堂工作坊：用 Prisma 把 todo 存進 PostgreSQL

到目前為止，todo 都存在記憶體裡，伺服器一重啟就消失。第 9、10 堂你學會了 SQL，這一堂用 **Prisma**（一個 ORM）把 todo app 接上 PostgreSQL：

```
寫 schema.prisma 描述資料表 → 用 migration 建表 → 產生 Prisma Client → 把 service 的陣列換成 Prisma 查詢
```

因為第 6 堂把資料存取都集中在 service，**這一堂只會改 service**，controller 和 routes 一行都不用動。

> 從[第 8 堂完成版](../08-testing-and-validation/完成版/)接著做。想知道「為什麼這樣寫」，每一步都有連結指向對應的[概念卡](../concepts/)。
>
> 卡住了？每個檢查點都對得上 [`完成版/`](./完成版/)，可以直接比對。

> ⚠️ 這一堂是新主題，**先不用 AI 工具**。自己把每一步走過，知道 Prisma 在做什麼，第 13 堂才判斷得了 AI 寫的資料層程式碼。

## 步驟 0：整理專案

接上資料庫後，第 7、8 堂的兩樣東西暫時不適用：

- `AGENTS.md` 寫著「資料存在記憶體、不要接資料庫」，已經不符合現況。
- `tests/` 的測試假設資料在記憶體裡（例如 id 1 一定存在），接上資料庫後需要另外準備測試用的資料庫。

這兩樣先移到別的地方保存（例如專案外的資料夾），[第 13 堂](../13-final-project/)會更新後再放回來。同時把 vitest、supertest 移除：

```bash
npm uninstall vitest supertest
```

再把 `package.json` 裡的 `test`、`test:watch` 兩個指令刪掉。

> 💡 Prisma 7 產生的程式碼是 TypeScript 檔，Node 要 **22.18 以上**才能直接執行。先 `node -v` 確認，版本太舊就 `nvm install 22` 更新。

## 步驟 1：建立資料庫、設定連線字串

用 `createdb` 建一個**新的**資料庫給 todo app 用：

```bash
createdb todo_app
```

> 💡 為什麼不用第 9 堂的 `todo_sql`？那個資料庫的表是我們手寫 SQL 建的。Prisma 要用自己的 migration 管理資料表結構，從一個空的資料庫開始最單純。

在專案根目錄建立 `.env`，寫入連線字串：

```bash
DATABASE_URL="postgresql://你的使用者名稱:密碼@localhost:5432/todo_app"
```

| 部分 | 意思 |
|---|---|
| `postgresql://` | 資料庫種類 |
| `你的使用者名稱:密碼` | 登入資料庫的帳號密碼。本機用 Homebrew 裝的 PostgreSQL，通常使用者是你的電腦帳號、不用密碼（寫成 `postgresql://帳號@localhost:5432/todo_app`） |
| `localhost:5432` | 資料庫在哪台電腦、哪個 port |
| `todo_app` | 資料庫名稱 |

確認 `.gitignore` 有 `.env`：連線字串裡有密碼，**不能 commit**。另外建一個 `.env.example`，放格式範例（不放真的密碼），讓別人知道要設定什麼：

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/todo_app"
```

> ✅ **檢查點 A**：`psql -d todo_app` 連得進去；`.env` 有 `DATABASE_URL`，而且被 `.gitignore` 擋住。

## 步驟 2：安裝 Prisma

```bash
npm install @prisma/client @prisma/adapter-pg dotenv
npm install -D prisma
```

| 套件 | 用途 |
|---|---|
| `prisma` | 命令列工具：migration、產生 client（只有開發時用，所以 `-D`） |
| `@prisma/client` | 程式裡用來查詢資料庫 |
| `@prisma/adapter-pg` | 讓 Prisma 透過 PostgreSQL 的驅動程式連線 |
| `dotenv` | 讀 `.env` 檔，把 `DATABASE_URL` 放進 `process.env` |

> ⚠️ 網路上的教學常叫你跑 `npx prisma init`。新版的 `prisma init` 除了建立設定檔，還會在專案裡裝一批給 AI 工具用的設定（`.agents/`、`.claude/` 等資料夾）。這一堂不用 AI，所以我們**自己建立**需要的兩個檔案，順便看懂每一行。

## 步驟 3：設定檔與 schema

在專案根目錄建立 `prisma.config.js`：

```js
// Prisma 的設定檔：告訴 Prisma CLI schema 在哪、migration 放哪、連哪個資料庫。
import 'dotenv/config' // Prisma 7 不會自己讀 .env，要在這裡載入
import { defineConfig } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
  },
  datasource: {
    url: process.env.DATABASE_URL,
  },
})
```

建立 `prisma/schema.prisma`，用 Prisma 的語法描述 todos 表：

```prisma
// 產生 Prisma Client 的設定：產出的程式碼放在 src/generated/prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

// 資料庫種類；連線字串寫在 prisma.config.js
datasource db {
  provider = "postgresql"
}

// 對應第 9 堂手寫的 todos 表
model Todo {
  id        Int      @id @default(autoincrement())
  title     String   @db.VarChar(200)
  completed Boolean  @default(false)
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz

  @@map("todos") // 資料表名稱用 todos（複數、小寫），跟第 9 堂一樣
}
```

對照第 9 堂的 SQL：

| 第 9 堂 SQL | schema.prisma |
|---|---|
| `id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY` | `id Int @id @default(autoincrement())` |
| `title VARCHAR(200) NOT NULL` | `title String @db.VarChar(200)`（沒有 `?` 就是 NOT NULL） |
| `completed BOOLEAN NOT NULL DEFAULT FALSE` | `completed Boolean @default(false)` |
| `created_at TIMESTAMPTZ NOT NULL DEFAULT now()` | `createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz` |
| 表名 `todos` | `model Todo` 加上 `@@map("todos")` |

`@map` 和 `@@map` 的用途：JavaScript 習慣 `createdAt`、`Todo`，資料庫習慣 `created_at`、`todos`。程式裡用左邊的名字，資料庫裡存右邊的名字，兩邊都照自己的慣例。

> 🧠 ORM 是什麼、跟手寫 SQL 比有什麼取捨 → [概念卡：ORM 是什麼](../concepts/orm-是什麼.md)

## 步驟 4：用 migration 建表

```bash
npx prisma migrate dev --name init
```

Prisma 做了三件事：

1. 比對 `schema.prisma` 和資料庫現況，算出要執行的 SQL。
2. 把這段 SQL 存成 `prisma/migrations/<時間>_init/migration.sql`。
3. 對資料庫執行它。

打開那個 `migration.sql` 看看，就是你第 9 堂會寫的 `CREATE TABLE`：

```sql
CREATE TABLE "todos" (
    "id" SERIAL NOT NULL,
    "title" VARCHAR(200) NOT NULL,
    "completed" BOOLEAN NOT NULL DEFAULT false,
    "created_at" TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT "todos_pkey" PRIMARY KEY ("id")
);
```

（`SERIAL` 是 PostgreSQL 另一種自動遞增的寫法，效果跟 `GENERATED ... AS IDENTITY` 一樣。）

**migration 檔要 commit 進 git。**它是資料表結構的變更紀錄，同事拉下程式碼後跑一次 `npx prisma migrate dev`，就能把自己的資料庫更新到一樣的結構。

> 🧠 migration 是什麼、為什麼不直接改資料庫 → [概念卡：migration](../concepts/migration.md)

```bash
psql -d todo_app -c '\d todos'
```

> ✅ **檢查點 B**：`prisma/migrations/` 底下有一個 `_init` 資料夾，`\d todos` 看得到四個欄位。

## 步驟 5：產生 Prisma Client

```bash
npx prisma generate
```

Prisma 讀 `schema.prisma`，在 `src/generated/prisma/` 產生查詢用的程式碼。之後每次改 schema 都要重新產生（Prisma 7 的 `migrate dev` **不會**自動幫你產生）。

產生出來的程式碼每個人都能自己產生，不用進 git。在 `.gitignore` 加上：

```
src/generated/
```

為了不用每次都記得手動產生，在 `package.json` 的 `scripts` 加上：

```json
"postinstall": "prisma generate",
"db:migrate": "prisma migrate dev",
"db:generate": "prisma generate",
"db:studio": "prisma studio"
```

`postinstall` 是 npm 的特殊指令：每次 `npm install` 完會自動執行。別人 clone 專案、`npm install` 之後，Prisma Client 就產生好了。

> ✅ **檢查點 C**：`src/generated/prisma/` 底下有 `client.ts` 等檔案，而且 `git status` 不會列出它們。

## 步驟 6：建立共用的 Prisma Client

建立 `src/db/prisma.js`：

```js
// 整個 app 共用一個 PrismaClient。
// Prisma 7 透過「driver adapter」連資料庫，PostgreSQL 用 @prisma/adapter-pg。
import 'dotenv/config'
import { PrismaPg } from '@prisma/adapter-pg'
import { PrismaClient } from '../generated/prisma/client.ts'

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL })

export const prisma = new PrismaClient({ adapter })
```

> 💡 為什麼 import 的路徑是 `.ts`？Prisma 7 產生的是 TypeScript 檔案，Node 22.18 以上可以直接執行 TypeScript（會自動略過型別的部分）。我們自己的程式碼還是寫 JavaScript。

整個 app 只建立**一個** `prisma`，其他檔案都從這裡 import。每 `new` 一次就會多開一組資料庫連線，到處 `new` 很快就會把連線用光。

## 步驟 7：把 service 換成 Prisma 查詢

打開 `src/services/todos.service.js`，把記憶體陣列和 `nextId` 刪掉，改成查資料庫：

```js
import { prisma } from '../db/prisma.js'
import { HttpError } from '../lib/httpError.js'

async function findOrThrow(id) {
  // /todos/abc 轉成數字是 NaN，不是合法 id，直接當作找不到
  if (!Number.isInteger(id)) throw new HttpError(404, '找不到這筆 todo')
  const todo = await prisma.todo.findUnique({ where: { id } })
  if (!todo) throw new HttpError(404, '找不到這筆 todo')
  return todo
}

function assertTitle(title) {
  if (typeof title !== 'string' || title.trim() === '') {
    throw new HttpError(400, 'title 必填，且必須是非空字串')
  }
}

export async function listTodos({ completed } = {}) {
  const where = completed === undefined ? {} : { completed: completed === 'true' }
  return prisma.todo.findMany({ where, orderBy: { id: 'asc' } })
}

export async function getTodo(id) {
  return findOrThrow(id)
}

export async function createTodo({ title } = {}) {
  assertTitle(title)
  return prisma.todo.create({ data: { title: title.trim() } })
}

export async function updateTodo(id, { title, completed } = {}) {
  await findOrThrow(id) // 先確認存在（404），再檢查欄位（400）
  if (title !== undefined) assertTitle(title)
  if (completed !== undefined && typeof completed !== 'boolean') {
    throw new HttpError(400, 'completed 必須是布林值')
  }
  if (title === undefined && completed === undefined) {
    throw new HttpError(400, '沒有提供要更新的欄位')
  }
  return prisma.todo.update({
    where: { id },
    data: { title: title?.trim(), completed }, // 值是 undefined 的欄位，Prisma 會略過不更新
  })
}

export async function deleteTodo(id) {
  await findOrThrow(id)
  await prisma.todo.delete({ where: { id } })
}
```

對照第 9 堂的 SQL：

| Prisma | SQL |
|---|---|
| `prisma.todo.findMany({ where: { completed: true }, orderBy: { id: 'asc' } })` | `SELECT * FROM todos WHERE completed = true ORDER BY id` |
| `prisma.todo.findUnique({ where: { id } })` | `SELECT * FROM todos WHERE id = $1` |
| `prisma.todo.create({ data: { title } })` | `INSERT INTO todos (title) VALUES ($1) RETURNING *` |
| `prisma.todo.update({ where: { id }, data: { completed } })` | `UPDATE todos SET completed = $1 WHERE id = $2 RETURNING *` |
| `prisma.todo.delete({ where: { id } })` | `DELETE FROM todos WHERE id = $1` |

幾個要注意的地方：

- **每個查詢都要 `await`**。第 6 堂把 service 都寫成 `async`，現在派上用場了。
- `id` 和 `createdAt` 都交給資料庫產生，`nextId` 不需要了。
- 這次換資料庫，**controller 和 routes 完全沒改**，因為它們只呼叫 service、不知道資料存在哪裡。這就是第 6 堂分層的好處。

`/notes` 這一堂先維持在記憶體，不用動。
