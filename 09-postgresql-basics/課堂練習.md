# 課堂練習：自己把多張表 JOIN 回來

> 這不是工作坊的延伸，而是**把這堂最核心的一件事再走一遍**——但這次沒有逐步指引，你得自己寫。
>
> 核心重點：資料拆成多張表後，怎麼用 JOIN（含 1:N、M:N、LEFT JOIN）把它們**拼回成你想看的那張結果表**。

工作坊帶你建好了 `lists`、`todos`、`tags`、`todo_tags` 四張表並灌好資料。現在你要**憑理解、不照抄 `queries.sql`**，自己寫出下面這幾條跨表查詢。

> 先把資料庫準備好（若還沒建）：
>
> ```bash
> createdb todo_sql
> cd 完成版
> psql -d todo_sql -f schema.sql
> psql -d todo_sql -f seed.sql
> ```
>
> 然後 `psql -d todo_sql` 連進去，逐題自己寫 SQL。

---

## 任務

用 `seed.sql` 的那批資料（3 個清單、6 筆 todo、3 個標籤），寫出以下查詢。**每題只准用一條 SQL 解出**：

| # | 你要查出什麼 | 會用到 |
|---|---|---|
| 1 | 每筆 todo 連同它所屬的**清單名稱**（沒清單的可以不出現） | 1:N `JOIN` |
| 2 | 每筆 todo 連同它的**標籤名稱**（一筆 todo 有多個標籤就出現多列） | M:N，穿過 `todo_tags` `JOIN` 兩次 |
| 3 | **每一筆** todo 都要出現，沒清單的那筆 `list` 欄顯示 `NULL`（不能被濾掉） | `LEFT JOIN` |
| 4 | 只看「工作」這個清單底下的 todo 標題 | `JOIN` + `WHERE` 用清單**名稱**過濾 |
| 5 | 每個清單的名稱，以及它**底下有幾筆 todo**（0 筆的空清單也要出現、顯示 0） | `LEFT JOIN` + `GROUP BY` + `COUNT` |

**明確規格**（這幾條就是這堂重點，別漏）：

- JOIN 的 `ON` 條件要接對欄位：1:N 是 `todos.list_id = lists.id`；M:N 要先 `todos → todo_tags`、再 `todo_tags → tags`。
- 第 3、5 題的「**不能漏掉沒對到的那一邊**」是 `LEFT JOIN` 與 `JOIN` 的差別所在——選錯就會少列。
- 第 5 題請數 `COUNT(t.id)` 而**不是** `COUNT(*)`：想想空清單那列為什麼會因此正確顯示 0。
- 多表查詢請給表取**別名**（`todos t`、`lists l`…），欄位用 `t.title`、`l.name` 寫清楚，避免 `id` 撞名。

> 💡 卡在「這題到底該用 JOIN 還是 LEFT JOIN」時，回去翻 [概念卡：SQL 關聯與 JOIN](../concepts/sql-關聯與join.md)。**不要翻 `完成版/queries.sql` 照抄**——憑記憶寫，寫不出來才回去看，這樣才練得到。

---

## 進階（行有餘力）

- 把第 2 題改成「每筆 todo 一列，標籤用逗號串成一格」（提示：`STRING_AGG` + `GROUP BY`，並要用 `LEFT JOIN` 才不會漏掉沒標籤的 todo）。
- 一條查詢同時帶出 **todo 標題 + 清單名稱 + 它的所有標籤**——想想三張、四張表一起 JOIN 時，列數為什麼會「膨脹」。

## 自我檢核

在 `psql -d todo_sql` 裡逐題跑你寫的 SQL，對照下面的**預期結果**。**全對才算完成**：

- [ ] **第 1 題**：回 6 列（每筆 todo 一列），每列都有 `title` 與對應的清單名稱（工作／生活／學習）。
- [ ] **第 2 題**：只回**有貼標籤**的那幾筆 todo——共 4 列（`寫專案週報→緊急`、`修登入頁的 bug→緊急`、`學會 SQL JOIN→長期`、`讀完 Express 文件→簡單`）。沒標籤的 todo 不該出現。
- [ ] **第 3 題**：回的列數 **≥ 第 1 題**；若你先 `INSERT` 一筆沒有 `list_id` 的 todo，它必須出現且 `list` 欄是 `NULL`（用 `JOIN` 會讓它消失，那就是錯的）。
- [ ] **第 4 題**：只回「工作」清單的 todo（`寫專案週報`、`修登入頁的 bug`），共 2 列。
- [ ] **第 5 題**：回 **3 列**（三個清單都在），`工作`=2、`生活`=2、`學習`=2；接著手動把某清單清空（或新增一個沒有 todo 的清單），該清單仍要出現且數字為 `0`。

驗第 3 / 5 題「不漏列」時，可以這樣製造一個邊界資料再重跑你的查詢：

```sql
-- 製造一筆「沒有清單」的 todo，和一個「沒有 todo」的空清單
INSERT INTO todos (title) VALUES ('沒歸到任何清單的事');
INSERT INTO lists (name) VALUES ('空清單');
```

- [ ] 加了上面兩筆後重跑：第 3 題看得到那筆 `list = NULL` 的 todo；第 5 題看得到 `空清單 = 0`。

> 五題全綠，代表你已經能獨立判斷「該用哪種 JOIN」並親手把多張表拼回來——這正是這堂、也是之後用 ORM 時你必須看得懂的底層。
